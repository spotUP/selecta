## Proposed fix rows (one per part above 500 ms)

1. I625a6a: font probe repeated for every setup, 2.7 s. Cause: `font_get` in plugins/shared/mcc/src/mui_aa_draw.c (line 102, probe at ~121-131, callers 222 and 242) caches only successes in g_fonts; a missing font runs mui_fontprobe_open (one DOS Open per name, with the requester guard) again for each of 160 aa_ctx setups. Fix: remember the failed probe result per (px, file list) for the process lifetime and reset it when the theme font list changes (mui_font_files / g_font_add), not by skipping the probe. Host test: with an ops stub whose open always fails, N setups at one px call ops.open exactly once per name; after the font list changes it probes again (the existing mui-fontprobe test is the place, via mui_fontprobe or a font_get seam). Also check whether the Inter font should ship in the release so the rig and users have it (open question, not measured with the font present).
2. I625a6b: first draw of the window, 745 ms (first Draw -> attempt returned). Cause not yet known: this span holds the draw of every object and any redraw MUI does after the open. Needs one more measurement row: per-class draw call count and elapsed time (aabtn, aatext, aalist, listview, canvas) via the same trace, before a fix row can name file:line. Host test to bound it: after the fix, the number of MUIM_Draw calls per class in the first draw is at most the visible object count (a counting seam in mui_contract_test or mui_aa_test).
3. Parts under 500 ms (not rows): AskMinMax + OpenWindow + Layout 116 ms, Show -> Draw 24 ms, window setup 89 ms. OpenWindow cannot be separated from AskMinMax and Layout by a class method trace (MUI sends no object method between them); if wanted, a Window hook or the intuition.library OpenWindow patch is a different facility and was not added.
