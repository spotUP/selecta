# I1207: click on an artist in desktop Search results does nothing

Mac track, plugins/ui/desktop/desktop_ui.c. Johan 2026-11-09: "clicking an artis in the search results does nothing".

## Root cause
Violated invariant: every drawn, clickable Search row has an entry in a per-frame click registry. Artists rows come from the
engine as key-less rows ("S <artist>" under "H Artists", src/engine/engine.c ~6490-6540, parsed in src/engine/view.c ~980-1110
with key=NULL). draw_search (list mode) and draw_grid_rows (grid mode) registered only keyed song rows, so the click handler
had nothing to hit. Single vs double click is not the issue: only song rows have a double-click handler.
Same navigation as the sidebar/Browse path: desk_route(SEL_ROUTE_META_ARTIST, ...) opens the collection page (kind artist) and pushes history.

## Fix
- desk gets search_art[48] + search_art_n/search_art_opens; reset per frame in draw_search.
- search_artist_reg() registers the visible rect of each Artists row (list) and tile (grid).
- Click handler on the Search page routes a hit to desk_route(SEL_ROUTE_META_ARTIST, ...).
- --stats dump line `searchartist <i> x y w h name=... opens=...`.

## Test
tests/dui/search_artist_click.cmake, ctest dui-search-artist-click, build/sdl (SELECTA_UI_DESKTOP=ON).
Types /huelsbeck, reads the artist row rectangle from the dump, clicks it, asserts `nav page=collection`,
`collection kind=artist`, and history pos >= 1.
- Red before fix: no searchartist row existed / no collection page (handler absent).
- Green after fix: dui-search-artist-click, dui-search-dblclick, dui-search-enter-focus and 12 other dui-search* tests pass (15 of 15).
- Revert-red: handler loop bound forced to 0, rebuilt: test fails with "a click on the Artists row must open the collection page". Restored, green.
Prereq on a fresh build/sdl: build targets sel_sqlite3_shell and tests/songs/selecta-test.mod, else dui-search* tests fail on setup.
