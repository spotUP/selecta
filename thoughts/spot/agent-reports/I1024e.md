# I1024e: ccMixter search through /api/query?search=, plus the dui-search golden fix

## Cause of the unstable dui-search golden
desk turn (plugins/ui/desktop/desktop_ui.c, the HOME/SEARCH repaint block) decided whether to repaint the Search view
from a shape-only signature: 0x10000 + row_count*64 + row_n. Each From section has one state row. That row changes
text from "Searching" to "Could not reach <name>" when its bucket fails, but the shape stays the same, so the page was
never marked dirty. The last frame showed the bucket states that had landed at the previous shape change. Two frame
dumps differed by exactly 12 glyphs ("Could not reach ccMixter" minus "Searching") and by the drawn list version (8 vs 9).
Neither old hash (4596bc1eadf5c320 / 77557e002b5b93ef) was the settled state.

## Fix
The signature now hashes the row content with the existing pl_hash(hv) (id, kind, depth, text per row), XORed with
row_count. Any state-row change repaints. The engine and the test are unchanged: the scripted run already waits until
no "Searching" row is left.

## Proof
- I blessed the golden once: 4082d42304548ac3.
- I then ran dui-search plain 3 times. All 3 passed against 4082d42304548ac3.
- Affected run: net-fixture-start/stop/selftest, radiobrowser-search, ccmixter-search, ccmixter, dui-search,
  dui-search-online, -badge, -online-quit, -online-live, -view-mode, -dblclick and dui-topbar-search-from-source
  all passed.
- dui-search-all timed out (176 s, limit 120) while another session's vitest used the CPU. When I ran it again
  alone, it passed in 40 s.
