# I972: MUI on RTG 800x600, text too small, sidebar gap at top

Johan, rig 2 (RTG 800x600 24-bit), verbatim: "the text is too small in 800x600 the left sidebar doesnt start from the top there is a gap".

## (a) Text too small: fixed

Root cause. The own screen opened without SA_Font (`mui_screen_open`, `plugins/ui/mui/mui_ui.c`), so it took the Workbench font (8 px bitmap). Two things draw in that font:

- MUI's stock objects (sidebar library list, all labels MUI draws itself), at every resolution.
- The AA classes' PLAIN backend. The AA classes pick `font_px = mui_aa_font_px(rows, cols)` (13 at 600 rows) and size the controls for it (`mui_aa_metrics`), but the text goes through ttengine plus Inter-Regular.ttf. Neither `LIBS:ttengine.library` nor `FONTS:Inter-Regular.ttf` is on rig 2 or rig 3 ("ttengine or Inter missing, plain text"), so the backend falls back to `_font(obj)`, the screen font: 30 px tall buttons with 8 px text.

Fix, at the existing decision point. New pure function `mui_aa_screen_font(font_px, &out)` (`plugins/ui/mui/map/mui_aa.c`) maps the tier size from `mui_aa_font_px` (single source) to stock Workbench 3.x `helvetica.font` at the largest stock size not above font_px + 1: 600 rows 13, 800 rows 15, above 18; the 256-row tier returns 0 and keeps topaz 8. `mui_screen_open` opens diskfont.library (renamed base, same reason as GfxBase in I719), `OpenDiskFont`s it, passes `SA_Font`; the font and library close after `CloseScreen` succeeds (kept open when visitor windows hold the screen). A missing font or diskfont logs a line and keeps the old behaviour.

Test: `mui-screen-font` (`tests/ui/mui_aa_test.c` `test_screen_font`): tier sizes plus a source check that `mui_screen_open` calls `OpenDiskFont(` and passes `SA_Font`. Revert-proven: returning a fixed size fails the size checks; dropping the SA_Font tag fails the source check.

## (b) Sidebar gap: not changed, conflicts with the Mac layout

The gap is the top bar row (I615d `mui_topbar_group`, RTG only), window-wide, above the HGroup(sidebar, main, detail). The sidebar starts below it (about 32 px buttons + 8 px spacing). This is the Mac truth: `src/uimodel/layout.c` `topbar_compute` gives a full-width 56 px top bar and puts the sidebar at y = tb_h; `desktop_ui.c` `draw_topbar` draws nothing at the left. Spotify's current desktop layout is the same.

To do what Johan asks, the root group becomes HGroup(sidebar, VGroup(topbar, HGroup(main, detail))) on the MUI side, or the Mac layout changes too (memory: Mac layout is the truth on conflicts). Decision for Johan; not implemented.
