# I1194: dui-list-key-frames fside Segmentation fault

Root cause: tag-number collision in include/selecta/tags.def. I1183 added SEL_UI_STAT_SIDE_CURSOR 0x50F2 and
SEL_UI_STAT_SIDE_CURSOR_DRAWS 0x50F3; I1184 had already added SEL_UI_STAT_TABLE_ACTIONS 0x50F2 and
SEL_UI_STAT_TABLE_ACTION_LOG (STR) 0x50F3. Each passed alone; merged, the desktop UI stat list answers
sel_tag_find(TABLE_ACTION_LOG) with side_cursor_draws. In run fside the sidebar cursor never drew (value 0),
so apps/selecta/main.c:1097 printed `log=%s` with a NULL pointer: lldb backtrace _platform_strlen <- __vfprintf <- printf <- main
(disassembly: tag 0x50f3 looked up for the log=%s printf). Crash at exit stats print, after q.
Same class as I603 (PT_MS_OVERLAY vs LIST_VIEW).

Fix at the layer with the bug (the tag table): I1184's two tags renumbered to 0x50F5 / 0x50F6.
Regression: existing ctest ui-stat-tags (tests/dui/stat_tags.cmake) fails on the old tags.def
("TABLE_ACTION_LOG and SIDE_CURSOR_DRAWS both use value 20723") and passes on the fix; it would have caught the merge
had it run on the merge commit. dui-list-key-frames fside is the end-to-end proof.

Landed: the fix is main e5314da7 (coordinator landed it while this agent was bisecting; this agent's identical edit was dropped).
Verification on the merged worktree (HEAD e5314da7): ctest ui-stat-tags and dui-list-key-frames both pass (fside included);
a fresh-db fside run exits 0 with the new binary (stats side_cursor=3 side_cursor_draws=3) and segfaults (rc 139) with the
pre-fix main-tree binary. Note: dui-list-key-frames needs target sel_sqlite3_shell built (a --target selecta build alone makes
it fail at "loading the fixture failed" with an empty error).
