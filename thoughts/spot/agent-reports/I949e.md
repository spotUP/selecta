# I949e: aspect consumers + tight metrics tier at 640x256 (closes I950)

Design: thoughts/shared/research/2026-11-01-I949-mui-640x256-design.md, section 4, section 5 (I949e), answer 4.

## Changed
- I950: `sel_surface.pix_aspect_q8` (0/256 square, 512 on 640x256 PAL). `vs_text_xy` (separate x/y scale), `vs_glyph_scale` (cap by
  column width, correct for pixel aspect). sidregs `labels()` uses it; the widest label "Voice1" stays inside 7 columns.
  `mui_viz_fit` fills the field from `mui_aa_screen_aspect()`; the desktop UI sets 0.
- Tight metrics tier: `mui_aa_metrics_aspect(font_px, aspect_q8, out)`; small font with aspect > 256 gives pad 4/2 rows, gap 4,
  height 12, icon 12x6, check 12x6. Square metrics unchanged. `mui_aa_rows`, `mui_aa_set/screen_aspect` (set once in
  `mui_screen_open`). AAButton measure/draw use `icon_h`/`check_h`; `aabtn_icon` samples rows nearest-neighbour.

## Reuse searched
I949a `mui_pixel_aspect_q8`/`g_pixel_aspect_q8`/`aspect_q8` field, `mui_player_band(..., aspect_q8)`, `vs_text`, `mui_aa_metrics`,
`aabtn_icon`, `mui_viz_fit`. grep `aspect` found no viz code reading pixel aspect. Extended, nothing duplicated.

## Tests
- `viz-sidregs` (`glyph_aspect`): square 320x224 heading stays inside its columns; 640x128 at aspect 512 gives a square glyph pixel.
- `mui-aa-aspect` (contract): metrics at 256/512, screen aspect set/get, AAButton and `mui_screen_open` wiring.
- Passed: viz-sidregs, mui-aa*, mui-icon-ratio (14 of 14 selected).
- Revert proof: with `labels()` set back to `sx = sy = rh / 7`, `sidregs_test all` fails twice ("heading overruns into the next voice: 280
  accent pixels", "glyph pixel 2 wide x 2 high, not square at aspect 512"); with the fix 0 failures.

## 36 px compact band
`mui_player_band` at aspect 512: art 56 wide gives 28 rows, plus 2*4 pad = 36 rows. One right row of 12-row buttons fits in 28 rows.
Transport and seek fit by the numbers; UNVERIFIED without the rig (MUIA_FixHeight is not set).
