# I1416a: network half of read_song moved to rd_play

Pre-edit statement
1. Invariant: the audio pump must never block on the network.
2. Ran on the pump: `src/engine/engine.c` read_song (called from prepare_slot): station resolve, .pls/.m3u resolve, live open with head/ID3 skip, sel_stream_read.
3. Moves to: play_meta_run on rd_play, via helpers net_station / net_stream. Result stored in sel_play_meta.net; read_song takes it (inline fallback when no library or no entry).
4. Cancel: thread-local sel_net_set_cancel(&e->open_cancel, e->pm_cancel_start) around the rd_play net work. cmd_STOP now calls cmd_CANCEL_OPEN. Live streams stay bound to cancel_gen with start pm_served (STOP / newer OPEN).
5. Tests: open-progress-engine (new leg e: slow URL, worst pump < 500 ms, STOP, destroy < 2 s, no SONG_OPENED), engine-library-follow-reads, library-close-cancel.

Unverified / left
- sel_live_drain in prepare_slot (whole download for non-streaming replayer) still blocks the pump; out of scope.
- CANCEL_OPEN alone does not interrupt a blocked live head wait (live bound to cancel_gen); result discarded on landing, bounded by net timeout. STOP and newer OPEN do cancel.
- record_to option read on rd_play from e->state.options (benign race).
- Re-open of same stream URL after its play-meta entry was consumed uses the inline pump path (not checked).
- cmd_STOP behaviour change: now cancels an active open and clears a deferred OPEN.
- Nothing run on Amiga or real UI.
