## What the code does

Stage 1 (timers). `krk_lava_fx.c` laps a clock around each stage of the fixed-point step and render; the plugin adds
inputs, palette and output. `stats()` appends ` stage_us forces N project N advect N particles N density N blur N light
N bloom N composite N inputs N palette N output N total N` (microseconds per frame, mean over the run). The Amiga clock
is `sel_clock_eclock()` (`src/core/amiga/clock.c`, timer.device `ReadEClock`).

Stage 2 (effect screen, design 3.4).
- New optional plugin hook `SEL_VIZ_INDEXED` (0x4006, `sel_viz_indexed_fn` in `include/selecta/viz.h`): the frame as the
  plugin's own 160x128 index image and its 256 colours. Krakatoa's FX build serves it from the same frame function as
  the RGBA32 path (`krk_frame` in `plugins/viz/krakatoa/krakatoa.c`); the RGBA32 path is unchanged for panes, RTG, the
  Mac and the tests.
- `desk_aga_direct_show` (`plugins/ui/desktop/amiga/backend_aga.c`): opens a second LORES 320 pixel, 8-plane, double
  buffered screen in front of the desk screen, loads the plugin's 256 colours with `LoadRGB32` when they change, scales
  the index image 2x with the in-between pixels interpolated in index space (`desk_aga_index_scale2`, `aga_planar.c`;
  valid because the ramp is one continuous gradient), converts it whole with the existing c2p kinds, flips. The next
  desk present closes the effect screen and converts the desk buffers whole.
- `viz_direct_frame` (`plugins/ui/desktop/desktop_ui.c`, AGA build only): the visual layout takes this path when the
  selected plugin has the hook and nothing draws in front of the visualizer (dialog, song menu, toast, tooltip).
- Sentinel for the rig: `desk_aga_close` prints `aga_direct opens=N presents=N c2p_kind=N scale_us=N c2p_us=N`.
  These two times come from the backend's own DOS clock (20 ms steps), summed over the run and divided by the number
  of presents: only the mean over many frames says anything. The backend does not use `sel_clock_eclock` because
  `selecta-aga-first-light` links `backend_aga.c` without the core library.
- Stages 1 and 2 are one commit: they change the same functions in `krakatoa.c`, `desktop_ui.c` and
  `krk_fx_plugin_test.c`, and were not split.

What the picture should gain, unverified: the effect gets all 256 pens in 24-bit colour instead of being quantised to
the desk palette, and fills a 320 wide screen instead of a region of the 640x256 desk canvas (no RGBA32 blit, no
quantise, no dirty bands).

Differences from design 3.4, on purpose, to be decided by a rig run: no user copper list. The image is scaled to 320 x
256 in fast RAM and all rows are converted, instead of converting 128 rows and doubling them with BPLxMOD. The copper
doubling halves the c2p cost and is the first thing to try once `c2p_us` is known.

## Proof that exists

- Host: `krk-core`, `krk-lava`, `krk-fx-plugin`, `dui-aga-planar` pass. `krk-fx-plugin` drives the plugin entry point,
  fetches the hooks from the descriptor, asserts the exact `stage_us` string under a fake clock, and for VIZ_INDEXED:
  160x128, more than 8 indices in use, the ramp equal to the settled Magma ramp, and the plugin advanced by the call.
  `dui-aga-planar` asserts the scaler's pixels (means, last column, last row, centre crop, fill past the image).
- Amiga: the AGA cross build (`build/amiga-aga`, `m68k-amigaos-gcc`, -Werror) of the whole product passes with both
  stages.

## Unverified

- Everything on the Amiga: that the effect screen opens, that the mode id (desk screen's mode with the hires bit
  cleared) is right, that keys stay with the desk window while the effect screen is in front (Esc must still leave the
  visual layout), that closing and reopening is clean, the frame time, the look. Looked at: nothing; the rig never
  answered.
- Whether `ui.desktop.mode=visual` in `prefs.conf` alone enters the visual layout on the Amiga.
- The `tags.def` row count test (`tests/CMakeLists.txt` 343) was not run after adding row 0x4006; the full host build
  was stopped to keep the machine free. Run `ctest -R tags` after a full build.
- The close button and the signal path line are not drawn on the effect screen.
- The MUI UI does not use the effect screen.
- When a rig does run: it runs the 68060 at host speed (`cpu_speed = max`) and does not model the chip bus. Its
  numbers rank the stages; they are not real 68060/50 frame times.
