# I1029: station click from Search freezes (beachball)

Sample: thoughts/spot/agent-reports/I1029-freeze.sample (main checkout). Main thread stuck in
prepare_slot > sel_live_drain > view_read_wait (usleep loop).

## Q1: why no streaming replayer for the search hit

The search path is not the cause. A search hit carries the same key as a synced row
(`radiobrowser:<uuid>/<name>`, built by search_row in src/engine/engine.c) and plays through the same
rb_play_url and sel_live path.

The cause is the station data. The top "chip" hit, "Retro Lofi Chiptune Radio"
(uuid bad4945f-cd86-42be-8ef4-72e0db167b45, https://a5.asurahosting.com:8150/radio.mp3), is listed by
Radio Browser as codec MP3 and served as Content-Type audio/mpeg, but its bytes start `ff f1 50 80`:
ADTS AAC. Selecta has no AAC replayer.

- plugins/replayers/minimp3/adapter.c:72 rp_probe says no (frame_len wants Layer III).
- src/engine/engine.c:2077 find_replayer returns NULL for the 16 KB head.
- src/engine/engine.c:2573-2592 prepare_slot then calls sel_live_drain "to read the whole file and probe again".
- src/library/stream_open.c:799 sel_live_drain loops in view_read_wait until EOF or SEL_STREAM_MAX
  (256 MB desktop): a radio stream never ends, so the engine thread, and with it the UI, hangs.

The synced stations played because they really were MP3 or Ogg. Any station whose stream no replayer
streams (AAC, HE-AAC, mislabelled codec) hits the same hang from any page.

## Violated invariant and level

Invariant: a whole-body read (drain) is only valid for a finite body. A radio (ICY) response has no end.
Level: the HTTP response record and the stream layer, which know whether a body ends. Not the engine
(it cannot know) and not the plugins (the codec label lies).

## Fix

- src/library/net/http.h / http.c: `sel_http_res.radio`, set before the first body byte when the server
  names itself a radio stream: "ICY" status line, or an icy-metaint, icy-name or icy-br header
  (icy-name and icy-br added to the kept headers).
- src/library/stream_open.c:
  - sel_live gets `endless`, stored (release) in sink_start before the first byte enters the ring, so the
    engine sees it once sel_live_head returned bytes.
  - sel_live_drain returns NULL at once for an endless stream; the engine reports plain open_failed
    (live status is still 0, so no misleading http_status=200).
  - sel_stream_read (the whole read used on Amiga and by non-live callers) aborts its sink on a radio
    response instead of reading up to SEL_STREAM_MAX (24 MB on Amiga).
- No engine change needed: the existing open_failed path already handles a NULL drain.

Not covered (separate row if wanted): an AAC replayer, so such stations actually play.

## Tests

- tests/net/icy_server.py: new endless station. The click on uuid eeee-5555 names
  http://icy.test/endless, an ADTS-AAC body under audio/mpeg with icy-name, icy-br, icy-metaint, no
  Content-Length, at 16 KB/s until the client hangs up; logs endless=1 and endless_bytes=<n>.
- tests/net/radio_endless.cmake, ctest `radio-endless` (label m3, net-fixture lock): reachability test
  through `selecta-cli script` with `OPEN radiobrowser:eeee-5555/Echo-AAC`. Asserts open_failed within
  10 s, no http_status, sentinels STREAMSOURCE resolves>=1 and STREAMLIVE opens>=1, fixture saw rb_click
  and the stream request, and fewer than 1 MB was read.
  The script runs with `--db` on a fresh database (the catalogue needs one for the radiobrowser cache
  directory; without it rb_play_url returns 0 and no request leaves).

## Results

- With the fix: radio-endless passes in about 1-2 s. Affected subset also passes: stream-url,
  stream-live, stream-live-ogg, stream-icy, radio-browser, radio, plus earlier http-client,
  stream-status, stream-record-play, stream-list, radiobrowser-search, stream-record.
- Revert proof: with the early return in sel_live_drain disabled (`if (0 && ld(&s->endless) ...)`),
  radio-endless fails: "I1029: OPEN of an endless stream hung (rc=Process terminated due to timeout)".
  Fix restored, test passes again.
- `cmake --build build/host --target lint` (-Werror build, SDK isolation, clang-tidy): rc 0.

## Not covered

- Mac GUI repro with the real station (Retro Lofi Chiptune Radio) is unverified here (no GUI in this
  run). Expected now: the click shows the open-failed state, no beachball.
- A real radio station whose server sends neither an ICY status nor any icy-* header and no
  Content-Length still falls into the 256 MB drain bound. Not seen in the sample; a follow-up row
  could treat a chunked/no-length audio response as endless too.
- AAC radio still does not play (no AAC streaming replayer); that is a separate feature, not this bug.
