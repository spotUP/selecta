# I961 nowait round trips unseen by the guards

Status: step 1 done; step 2 partly done (call structure, one measured number); step 3 OPEN (not started).

## Step 1 (done)
Root cause: sel_library_request (src/library/db/worker.c) took t0 and counted g_watched_waits / g_watched_wait_ms only when !g_nowait. A nowait request that wins the call-lock trylock still blocks on lib->lock/wake_caller until the worker answers, so lib_ui_watched_waits and lib_ui_wait_ms missed it. Fix: count whenever g_watch; a deferred request (trylock failed) returns before counting and is still not counted.
Test: engine-library-ui-nowait (tests/engine/library_ui_nowait_test.c), new block: nowait on, call lock free, SEL_LIB_REQ_STATS must raise watched_waits by exactly 1 and not deferred; a deferred try must not count. Revert proof: with HEAD worker.c the test FAILS (watched_waits == w1 + 1u); with the fix it passes, with engine-library-ui-guard and engine-library-nowait.
The old post-release assertion (watched_waits == 0 after the library is freed) was removed: it only held because nowait was uncounted. The busy-library I829 check (pump < 50 ms, 0 waits while the worker is held) stays. The test now prints "i961 nowait round trips on the pump thread after release: 12".

## Step 3 (I961c): writer-kept mirror for SOURCES and the playlist keys

Design source: thoughts/shared/research/2026-11-01-ui-thread-library-waits.md (I906 design, commit ad1a2449), section 1 "Existing async patterns to reuse" (rating_pending_n writer counter, I948a posted read) and section 2b/2c site table (cmd_SOURCES, pls_reload).

Site of the waits. dui-collection-open-touch counted 98: cmd_SOURCES 3 bursts of 32 (96) plus pls_reload 2 (the playlist key read). The other four tests counted 32 each, cmd_SOURCES only.

Mirror (src/library/db/srcmirror.c). The writer keeps per-source song counts and sync times in lib->src_mir (db_internal.h), rewritten under a sequence counter at the end of sel_library_handle (db.c), before the reply goes out, so a caller reads its own write. sel_library_source_songs and the new sel_library_source_synced copy it; cmd_SOURCES and sync_time_get (engine.c) issue no request. Gotcha found by the regression test: sqlite3_update_hook never fires for WITHOUT ROWID tables, and both source_songs and meta are WITHOUT ROWID. The hook therefore watches the rowid table songs (every source_songs change comes from its triggers; with an attached index the idx.songs table too), and the sync times (a handful of meta rows, key range sync.) are re-read on every refresh. With an index attached the recount is skipped while more requests wait, so a scan burst pays for it once.

pls_reload. The keys read is now an engine posted read (sel_engine_playlist_keys_post/_busy/_take, engine.c, same pattern as the I948a song_briefs read); pls_reload_run posts, sets pls_stale, and takes the answer on a later frame. An answer for another playlist id is dropped and re-posted. The blocking sel_engine_library_playlist_keys is removed.

Tests. The five tests are green with watched_waits == 0 unchanged: dui-files-tab-first-frame, dui-collection-open-touch, dui-song-panel-art-async, dui-stats-nowait, dui-direct-calls-async. engine-library-ui-nowait is green and carries the new regression block: after a META write it reads the sync time and count from the mirror, then sends SOURCES through sel_engine_send_line and sel_engine_pump and asserts lib->served and the watched waits do not move. Revert proof: a probe that makes sel_library_source_songs issue one worker request turns the test red; removing the probe turns it green. 20 related source, sync and playlist tests are green.

Not mine, left red: library-scan-small-heap (fails identically with the older main build binary on this fixture, peak heap is lower with this change: 348768 vs 352800), library-items-budget (timing, albums warm 1742 ms), engine-library-items line 206 (LIBRARY_TOUCH goes through the write queue; not touched by this change; not compared against a clean main build, unverified). Known red, untouched: dui-sidebar-library, dui-playlists, dui-search, dui-search-online.
