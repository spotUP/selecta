# I1416b report

- read_song's sel_library_fetch fallback removed: play_meta_run (rd_play) now also fetches a station that resolves to a remote library key (net_station result), filling the same fetch_* fields read_song already takes. A stray remote key with no covering fetch now fails the open instead of downloading on the pump (open_fetch_ms_max stays 0).
- cmd_LIBRARY_FETCH runs on a new lib_read slot rd_fetch (fetch_run), not the writer queue: wq ops get only the lib pointer (no cancel counter) and one multi-minute download would block every other library write. Cancel counter fetch_cancel is bumped by CANCEL_OPEN (so STOP), a new OPEN of another path, and destroy. Answer is taken in the pump pass (LIBRARY_RESULT, md5_mismatch, fetch_failed; none when cancelled). A second fetch while one runs answers library_busy.
- Test: open_progress_engine_test leg (f): LIBRARY_FETCH of bigslow.mod keeps pump < 500 ms, STOP + destroy < 2.5 s (download is 3 s).
- ctest: open-progress-engine, engine-library-follow-reads, library-close-cancel, cache-fetch, cache-fetch-shell pass.
- Unverified: Amiga build; a successful LIBRARY_FETCH result event through the new path is covered only by cache-fetch / cache-fetch-shell (CLI), not by the new leg. One other session's ctest (art|cover) ran at the same time.
