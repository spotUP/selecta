## Cause (I1246b)

`sel_viz_acquire` (src/engine/viz.c) delayed frames by counting acquire calls (UI frames), not audio
blocks. The delay is set from CoreAudio output latency in 20 ms blocks (engine.c, `(out_latency_ms*50+500)/1000`).
At 50 fps UI one acquire is one block, so it was right; below 50 fps each queued step lasts a UI frame,
so the visual lag grows to delay x UI frame interval. Krakatoa's heavy GPU step drops the UI frame
rate, which is exactly when the lag shows.

## Fix

The delay queue now selects by frame sequence: after enqueuing the newest frame it pops while
`queue[head].seq + delay <= newest_seq` and shows the last popped frame. Lag is now exactly the
output latency at any UI frame rate.

## Open: I1246a (kick pump not visible)

Tried a divergence volume source in the DIV pass (`u.tm.w * exp(-|c-bp|^2 / (1.5*bp.w)^2)`, pump x 80,
then x 2000): no measurable image change at kicks (detrended rise ~0 px, frame diff unchanged ~1.6).
The trace shows the frame ~97% lit (blue > 40), centre ~240: the harness image is saturated with smoke
(also with auto wander and with the real song). Two candidate causes, not separated yet:
1. saturation hides any motion (density/emission too high in the harness view), or
2. the projection (Jacobi 28 iterations, warm start 0.85) removes the source before it moves density.
The volume-source change was reverted (patch kept out of tree); next step is to measure velocity
magnitude at the brush before and after the pressure pass, then density at an unsaturated setting.

Remaining lag after this fix: detection one block late (~30 ms) plus ~40-80 ms smoke rise. Halving
the spectrum window (last 512 frames) would cut ~10 ms; not done, needs its own row.
