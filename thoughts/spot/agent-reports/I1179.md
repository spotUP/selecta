# I1179 MUI song context menu (I799 C1, C2)

Root cause: plugins/ui/mui/mui_ui.c mui_song_context_menu built the five song items only. Item 4 was always "Remove from Library"
(never "Remove from Queue" on a queue entry), there was no Rename/Delete for playlist rows, and the items never followed the cursor row.

Fix: shared rule in uimodel (include/selecta/uimodel/viewcmds.h, src/uimodel/viewcmds.c): sel_uim_ctx_mask, sel_uim_song_menu_n,
sel_uim_plremove_label/line. Desktop song_menu_count/label and PLAYLIST_REMOVE_SONG now use them. MUI: mui_ctx_kind (map/mui_views.c),
mui_ctx_sync in mui_ui.c (called after each list refresh) enables items from the mask and swaps item 4's title; the strip gains Rename and
Delete (P4_PRENAME / P4_PDELETE ReturnIDs).

Exemption: Remove from Playlist is not shown in the MUI. The MUI has no playlist-songs page (a playlist row plays on activate), so no
row can carry it. Shared label and line exist for when it lands. Folder rows map to none (P4_PDELETE has no folder branch).

Test: mui-ctxmenu (tests/ui/mui_contract_test.c test_ctxmenu). Green with the fix; red when the mui_ctx_sync call is removed from the
refresh (verified); before the fix it does not compile (mui_ctx_kind absent). Also green: mui-song-menu, mui-playlists.
Builds: build/host mui_contract_test + sel_plugin_desktop_ui OK; build/amiga sel_plugin_mui_ui + sdkcheck + incheck OK. No rig run.
