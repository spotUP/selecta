# I1030: All sources search shows no "From Radio Browser" section

## Root cause

plugins/ui/desktop/desktop_ui.c, desk_search_fire (`VIEW_WINDOW %u` with SEARCH_WINDOW_ROWS = 64, enum at the old line 8696,
send at line 8917 before the fix).

The engine builds the search view text in this order: the library groups Songs, Albums and Artists (heading plus up to 16 rows
each, up to 51 rows), then one "From <name> (n)" section per source bucket, in registry order: Internet Archive (up to 41),
Modules.pl (up to 41), Radio Browser. The Search page draws the whole grouped result and scrolls it in pixels (search_q16).
It never moves the view window. But it asked the engine for a 64-row window, so only rows 0..63 of the search text reached
st->view->rows. With an empty library (the old dui-search-all case) all sections fit inside 64 rows. With a library that
matches the query (Johan's real library), the From sections start past row 51, and Radio Browser, the last bucket, starts past
row 64. The bucket ran and its rows were in the engine's text; the UI never received them. The Radio Browser chip path
(scope one source) draws the online rows and is not limited by the window, which is why the chip shows hits.

The engine side was correct: search_reload_sources writes every bucket, and VIEW_WINDOW accepts up to row_cap (256).

## Fix

- include/selecta/engine.h: SEL_VIEW_WINDOW_MAX (256) moved here from src/engine/view.h. One source of truth for the largest
  window, now visible to the UIs. 256 is also the most rows a home or search text holds (SEL_VIEW_FOLDER_ROWS).
- plugins/ui/desktop/desktop_ui.c: SEARCH_WINDOW_ROWS = SEL_VIEW_WINDOW_MAX, so the Search page gets every row it draws.
  The grid and cover flow tiles buffer (sized by the same constant) is now static, to keep 256 rows off the stack. The song
  registry is unaffected: it registers only rows inside the list rect and stops at SM_ROWS.

## Regression test

tests/dui/search_all.cmake (ctest dui-search-all), new I1030 block. It loads a library db with 40 songs that match "chip"
(distinct names, artists and albums, so Songs, Albums and Artists each have 16 rows). It then types "chip" on the Search
page on All sources, through the scripted --input feeder of the real desktop shell (--ui desktop --backend mem), with
modulespl, archiveorg and radiobrowser all answering from the net fixture. It asserts `search groups songs=40` and
`search_section N rows=2 From Radio Browser (2)`. This is the sentinel: the radiobrowser bucket ran and its 2 rows reached
the section, with a full library above it.

- Before the fix: FAIL. The dump shows only `From Internet Archive (8)` and `From Modules.pl (3)`; view_rows=66.
- After the fix: PASS (dui-search-all, 39.7 s).
- Fix reverted (SEARCH_WINDOW_ROWS = 64 again, rebuilt): FAIL with the same I1030 message. Fix reapplied: PASS.
