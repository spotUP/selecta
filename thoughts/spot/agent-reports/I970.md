# I970: icon baker keeps detail in the 16x8 tall-pixel set

## Cause
tools/gui_iconbake.c raster_wh supersampled the 24-grid Lucide paths with an isotropic half-stroke and no grid fit.
In the 16x8 set (tall pixels, 1:2) 1-px horizontal strokes straddled row boundaries, and write_mui quantised alpha to
4 pens (thresholds 48/112/184). Result: list middle bar became two pen-1 rows, repeat arrowheads merged into a blob,
stop had double-wide pen-3 verticals, pen-1 horizontals and soft corners.

## Change
raster_wh dispatches non-square sets to a new raster_fit (fseg, fit_axis, fit_segments, fdist2). Axis-aligned segments
and dots snap both ends to pixel centres on both axes (value keyed, so curves ending on a fitted line move with it);
axis-aligned strokes use half-width 0.5 px per axis, other strokes max(src*k, 0.5) per axis. Square sets keep the old
supersampler (bit-identical). The baked mui_icons_baked.c is generated into the build dir and is not tracked.

## Test
tests/ui/mui_icon_fit_test.c (ctest mui-icon-fit, label mui) reads the baked 16x8 bodies: list 3 full-pen bar rows
with clear rows around and 3 bullets; repeat arm ends/tips full pen, arrowheads separate, 2 full horizontal rows;
stop single-pixel edges at equal pen.

## Revert proof
ctest mui-icon-fit: new baker Passed; old baker copied back and rebuilt: Failed (5 failures standalone); new baker
restored: Passed. Not run: existing icon tests (mui-sidebar-icons etc.; need a ~770 step build); square sets are
unchanged by construction.
