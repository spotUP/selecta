# M0b: machine probe, voices, fixed-point mixer, nuade adapter, `wav` + `coreaudio`, `selecta-cli render`, golden tests

Implements design doc `thoughts/shared/plans/2026-10-22-architecture-design.md` section 4 (replayer SDK tag list, `sel_voices` with `set_period`, sample memory rule), section 5 (two sink classes, fixed-point mixer 16.16 phase / 32-bit accumulate / int16 out, `SEL_MIX_RESAMPLE_NONE/LINEAR/CUBIC/SINC`, `wav` as oracle and record path), section 12 (`sel_machine` tag list, `selecta-cli machine`), section 13 (golden WAVs on desktop and 68k) and section 14 (rest of M0). ## Decisions taken in this plan (not open)

- **nuade source.** Git submodule `third_party/nuade` from `https://github.com/emoon/nuade`, pinned at `111c9657965f00e9a94fec3545ce238d43af57f4` (2026-10-13, the commit DEViLBOX's `UPSTREAM.md` names; existence verified with `gh api` 2026-10-22). No edits inside it (rule 5); any needed change is a patch in `third_party/patches/nuade/` applied by CMake at configure time, and none is expected.
- **Players in M0b.** One: `protracker4` (its own sources use no float; checked with grep over `players/protracker4/*.c`, zero hits). Selected with nuade's own `cmake/nuade_players.cmake` (`NUADE_PLAYERS=protracker4`), reused, not rewritten. All 121 players, their per-player licence review and the companion-file `NuadeIo` are M1.
- **nuade is compiled as C11** (its CMakeLists sets `c_std_11`, extensions off) in its own static target `selecta_nuade`; Selecta code stays C99. Our warning flags apply to adapter code only; nuade sources get nuade's own flags. gcc 6.5 supports C11; I32 proves it on the 68k build.
- **What of nuade we link.** Players + `nuade_registry.c`, `nuade_paula_channel.c`, `nuade_tracker.c`, `nuade_file_index.c`, `nuade_path.c`, `nuade_grid.c`, `nuade_viz.c`, `nuade_scheduler.c`. Not linked into the plugin: `nuade_mixer.c` (float mixer), `nuade_song.c` (its render loop owns the mixer), `nuade_io_default.c` (`<sys/stat.h>`). The adapter defines `struct NuadeVoices` and every `nuade_voice_*` function plus `nuade_voice_muted` and `nuade_instrument_muted` (the full set players call, counted from the players' call sites: 10 functions), forwarding to `sel_voices`. Link-level replacement, nothing patched.
- **Float stays in the adapter shim.** nuade's voice API takes `double hz`, `float volume`, `float pan`; the shim converts once per voice call at tick time to Q-format integers (`hz` to 24.8, `volume` to Q16 0..65536, `pan` to -32768..32767). Nothing per sample. On desktop and under vamos this is legal (not an interrupt path). Paula-direct ticking under a CIA interrupt on a 68020 without FPU would violate rule 4; that is decision row D-M2-1 in the ledger, not M0b work.
- **Scheduler and repeat logic live in the engine**, not the adapter: `src/engine/scheduler.c` reimplements nuade's integer remainder-carry (`src/nuade_scheduler.c:8-11`) over `sel` types, because the engine schedules every VOICE-kind replayer (design section 4), not only nuade. The adapter's `SEL_RP_TICK` returns `{length in timebase units, flags}` exactly as nuade's `NuadeTickResult`.
- **`sel_voices` (new `include/selecta/voices.h`).** Shape of nuade's voice API with integer arguments:

  ```c
  typedef struct sel_sample {
      const void* data;      /* plugin memory (SEL_MEM_SAMPLE); read live */
      uint32_t format;       /* SEL_SAMPLE_S8 or SEL_SAMPLE_S16 */
      uint32_t length;       /* frames */
      uint32_t loop_start;   /* frames */
      uint32_t loop_length;  /* frames; 0 = one-shot */
  } sel_sample;

  typedef struct sel_voice_state {
      uint32_t playing;
      const sel_sample* sample;
      uint32_t position;     /* source frames, integer part */
      uint32_t pitch_q8;     /* Hz, 24.8 */
      uint32_t volume_q16;   /* 0..65536 */
      int32_t  pan;          /* -32768..32767 */
  } sel_voice_state;

  struct sel_voices {
      uint32_t size;         /* sizeof(sel_voices) of the host build */
      void (*play)(const sel_voices*, uint32_t voice, const sel_sample*, uint32_t start_frame);
      void (*queue)(const sel_voices*, uint32_t voice, const sel_sample*);
      void (*stop)(const sel_voices*, uint32_t voice);
      void (*set_pitch_hz)(const sel_voices*, uint32_t voice, uint32_t hz_q8); /* 0 = hold */
      void (*set_period)(const sel_voices*, uint32_t voice, uint32_t paula_period);
      void (*set_volume)(const sel_voices*, uint32_t voice, uint32_t volume_q16);
      void (*set_pan)(const sel_voices*, uint32_t voice, int32_t pan);
      int  (*is_playing)(const sel_voices*, uint32_t voice);
      void (*get_state)(const sel_voices*, uint32_t voice, sel_voice_state* out);
      void* ctx;
      /* append only below this line */
  };
  ```

  `sel_host` layout does not change (the `voices` accessor exists since M0a), so T6 goldens stay as they are. A new `selecta-cli abi` section prints `sel_voices` offsets and gets goldens for x86_64, arm64, m68k.
- **Mixer** (`src/mixer/mixer.c`, `include/selecta/mixer.h`, engine-internal). Per voice: 16.16 phase, step from `set_period` as `((uint64_t)3546895 << 16) / (period * rate)` (PAL clock) and from `set_pitch_hz` as `((uint64_t)hz_q8 << 8) / rate`; 32-bit stereo accumulators; int16 output with saturation. Loop, one-shot and queue semantics follow `nuade_mixer.c` `settle()` (l.322) so the A/B test is meaningful. Resamplers: NONE (nearest, nuade's own behaviour), LINEAR (Q15 fraction), CUBIC (4-point Catmull-Rom, Q15 coefficients), SINC (8-tap windowed sinc, 256 phases, Q15 table generated at build time by `tools/gen_sinc_table.c` into the build tree; float used only in that host build tool, never in the engine). Default from `sel_machine`: `FPU=0` or CPU below 68040 gives LINEAR, 68040/68060 gives CUBIC, desktop gives SINC. The golden tests pin the resampler on the command line so the hash does not depend on the machine.
- **Pan and separation.** Pan law linear (integer `(32768 - pan)` / `(32768 + pan)` split), separation default 100 % as in nuade (`stereo_separation = 1.0f`, `nuade_song.c` l.60). Paula LED filter emulation and per-song gain are not M0b.
- **Machine probe** (`src/core/machine.c` common, `src/core/macos/machine.c` with `sysctl`, `src/core/linux/machine.c` with `/proc/meminfo`, `src/core/amiga/machine.c` with `SysBase->AttnFlags` and `AvailMem(MEMF_CHIP|MEMF_TOTAL)` / `MEMF_FAST`). Measured `CPU_SPEED` and float throughput use a fixed integer loop timed by `clock_ms`; GFX, AUDIO, NET, DISK report `unknown` in M0b and get real probes with the outputs and UIs that need them (M1, M2). `tags.def` gains the `SEL_MACHINE_*` rows; tags only, no struct.
- **Song input.** `selecta-cli render` and `play` read the whole file into memory with C stdio and pass a `sel_song_source {data, size, path}`; the adapter wraps it as `NuadeSongSource` with an `NuadeIo` whose `read_url_to_memory`, `exists` and `list_dir` report "not found" (protracker4 needs no companion files). Host file open for companions is an M1 row with an append to `sel_host`.
- **Test song.** `tools/gen_testmod.c` (host build tool) writes `selecta-test.mod`: 4 channels, 4 patterns, 8-bit samples synthesised with integer math (square, saw, noise from an LFSR, a decaying click), effects 0xx, 1xx, 2xx, 3xx, 4xx, Axx, Cxx, Fxx so the golden covers period slides, vibrato and volume work. Generated at build time into `build/host/tests/songs/`; its SHA-256 is pinned in `tests/songs/selecta-test.mod.sha256` and checked by the test. No third-party module, so no licence question.
- **Golden hashes** are produced once by the host build, reviewed by listening (Blocked on me item), and committed as `tests/golden/nuade/selecta-test.<resampler>.sha256` for all four resamplers. T13 checks `linear`; `mixer-unit` covers the resampler maths; the other three hashes are checked by `render-golden-host` sub-cases (one ctest each: `render-golden-host-none`, `-cubic`, `-sinc`).
- **Outputs.** `plugins/outputs/wav/wav.c`: PCM sink, C stdio only, writes RIFF/WAVE PCM16 little-endian on every CPU (explicit byte writes), header sizes patched at close. `plugins/outputs/coreaudio/coreaudio.c` (macOS only, links AudioToolbox): default output AudioUnit, render callback pulls `sel_pcm_pull`, which calls `sel_engine_render` on the audio thread; commands and events cross through the M0a SPSC queues. This is the first audio thread; `sel_engine_render` gets a `SEL_THREAD_AUDIO` assertion in debug builds.
- **Engine verbs implemented here:** `OPEN path` (probe, open, emits `SONG_OPENED {SEL_META_*}`), `SUBSONG n`, plus events `SONG_ENDED` and `POSITION` from tick flags. `SEEK` stays `not_implemented` (needs replay from start, M1).
- **sdk-isolation (T7)** keeps `-I include` only for every plugin, except that a plugin may list its own `third_party/<lib>/include` directory in `selecta_plugin(... THIRD_PARTY_INCLUDES ...)`; the nuade adapter lists `third_party/nuade/include` and nothing else.
- **no-float check (T18)** reads 68k object files with `m68k-amigaos-nm`, because libgcc soft-float calls are the exact thing rule 4 forbids on a 68020 without FPU. Host builds rely on T18 plus review.
- **Amiga CI image** (carried from M0a I21): stays a separate open row I44; not a finish-line item.

## Deviations

- Phase 1: resampler choices are enum constants in `include/selecta/machine.h`, not tags; only `SEL_MIX_RESAMPLE` (INT, MIX block 0xB000) is a tag. `FPU_SPEED` is an integer-loop proxy because `src/core` holds no float. Extra files: `src/core/machine_internal.h`, `apps/selecta-cli/machine.c`.
- Phase 1 follow-up: the platform probes and the Amiga clock moved to `src/core/<os>/` (`macos/`, `linux/`, `amiga/`) so OS headers sit only where RULES.md rule 3 allows them. `src/host/clock_amiga.c` predated this and is now `src/core/amiga/clock.c`.
- T12 period step for 428 at 44100 Hz is 12315 (`(3546895<<16)/(428*44100)` truncated), not 12316.
- Phase 2: `mixer.h` lives at `src/mixer/mixer.h` (not `include/selecta/mixer.h`); the `SEL_MIX_RESAMPLE_*` constants live in it. `sel_resample_sinc_row` returns `int32_t` rows (32768 does not fit int16). `sel_voices` backend is `src/engine/voices.c` inside `selecta_core`.
- Phase 2: `mixer_test` takes group arguments so each resampler enters the ctest gate with its row. The red commit used stub `mixer.c`/`resample.c`/`voices.c` so the failure is a ctest failure, not a link error.
- Phase 2: `set_pitch_hz`/`set_period` with 0 means hold. Interpolation taps do not look into the queued sample. Mutes and separation are not in the mixer yet (engine, Phase 3). The SINC table has no source-rate prefilter. The T18 no-float check (m68k nm on mixer objects) is not part of Phase 2 rows.
