# Selecta M4: ARexx port

Implements design doc `thoughts/shared/plans/2026-10-22-architecture-design.md` D7 (line 552), section 16 (line 458: "an ARexx port maps 1:1 onto the same commands so HippoPlayer-style ARexx scripts port by renaming the port"), the reflection and atomic-list bullets of the protocol additions (lines 185, 190), the song-change hook (line 194), the layout line `plugins/scripting/ arexx/ (amiga)` (line 474) and the M4 row (line 520). M1.2 names the ARexx port as the Amiga equivalent of the control socket (`2026-10-23-m1-2-playlists-views-control.md:53`, `:143`).

## 1. Goal and finish line

Any Amiga program (ARexx scripts, Amarchy, Directory Opus, HippoPlayer scripts with the port renamed) controls everything in Selecta through a public ARexx port, and reads results back in `RESULT`.

Finish line: on the Replay Amiga, with Selecta running the text UI, an ARexx script run through the amiga MCP (`amiga_rexx`):
1. finds the port `SELECTA` (`amiga_arexx_ports`);
2. sends `OPEN <mod>`, `PLAY`, `VOLUME 40`, `STATUS`, and gets `RC=0` for each;
3. reads back a `STATUS` result with `state=playing`, the song title, and `volume=40`;
4. reads back `COMMANDS` with 103 or more lines (one per verb in `commands.def`, counted from the generated table, not grepped);
5. gets `RC=10` and an error text in `RESULT` for an unknown verb;
6. sends `QUIT`, after which the port is gone and the process has exited.
Selecta's `--stats` output shows `arexx_cmds=N`, the sentinel that the port code ran (same pattern as `socket_cmds`).

## 3. Shared reply layer (host and Amiga)

One function turns a protocol line into a reply, used by the socket, the ARexx port and `selecta-cli`:

`int sel_ctl_exec(sel_engine* e, const char* line, char* reply, size_t cap, int* rc)` in `apps/common/ctlexec.c` (lifted out of `ctl_handle` in `apps/selecta/main.c`, not copied). It sends the line, pumps the engine, and builds the reply from the events of that line:
- error: first `ERROR` event, `rc = 10`, reply `<code> <text>`;
- result: the `RESULT` events of that line, one per output line, joined with `\n`, `rc = 0`;
- otherwise `rc = 0` and an empty reply (the socket still writes `OK`, so current clients do not change).

New event `RESULT "s"` in `events.def`: one line of a command's answer. `COMMANDS`, `EVENTS`, `TAGTYPES` and `STATUS` emit `RESULT` lines instead of `LOG` lines. The socket reply becomes `OK` followed by the result lines and a closing `.` line (the mpd and SMTP convention), only for verbs that emit results. A reply that does not fit `cap` ends with `ERROR result_truncated`, never silently cut.

## 4. Protocol additions

### 4.1 STATUS

`STATUS` (no arguments, area `protocol`) emits one `RESULT` line per field, `key=value`, from `sel_engine_state`:
`state=playing|paused|stopped`, `title=`, `composer=`, `path=`, `subsong=n/m`, `position_ms=`, `duration_ms=` (0 when unknown), `volume=0-100`, `repeat=off|all|one`, `random=on|off`, `queue_pos=n/m`.
Values are not quoted; a value ends at the end of the line. ARexx scripts parse it with `PARSE VAR`.

### 4.2 QUIT

`QUIT` (area `protocol`) asks the shell to end the run the same way the text UI's quit key does (same exit path, same stats output). Over ARexx the port replies first, then closes.

### 4.3 COMMANDS, machine-readable (Amarchy request, 2026-10-25)

`commands.def` gets two columns: `SEL_CMD(id, args, area, argnames, label)`, for example `SEL_CMD(VOLUME, "i", "transport", "level", "Volume")`. A build-time check fails when a verb has no label or when the number of argument names does not match the argument letters.

`COMMANDS` emits one `RESULT` line per verb: `VERB [argname ...]<TAB>Label<TAB>args=<letters> area=<area>`, for example `VOLUME level\tVolume\targs=i area=transport`. The first two fields are the format Amarchy asked for (`VERB [arg-name ...]`, tab, label), so its menu rows take their labels from the port. The third field keeps the signature and area that the command palette and the help overlay already read. Optional arguments are written `[name]`, repeating ones `name...`.

Labels are full English words (global rule): `Previous Album`, not `Prev Album`.

## 5. ARexx port (Amiga)

`plugins/scripting/arexx/` (design doc line 474), a scripting plugin built only for `__amigaos__`, opened by the shell at start when `rexxsyslib.library` opens; without it Selecta runs on with `arexx=off` in the stats output.

- Port name: `SELECTA`. When `FindPort("SELECTA")` finds one (a second Selecta), the next free name `SELECTA.2`, `SELECTA.3` (HippoPlayer and AmigaAMP practice). Created with `CreateMsgPort` plus `AddPort` inside `Forbid`/`Permit` after the `FindPort` check.
- Each turn of the shell loop: `GetMsg` until empty. For each `RexxMsg`: `ARG0(msg)` is the line; `sel_ctl_exec` runs it; `rm_Result1` = `rc` (0 OK, 10 error); when `RXFF_RESULT` is set and `rc == 0`, `rm_Result2 = CreateArgstring(reply)`; when `rc != 0` and `RXFF_RESULT` is set, `RESULT` holds the error text too (standard `RC`/`RESULT` only, no extra ARexx variables). `ReplyMsg`.
- `IDLE` over ARexx would hold the message and block the caller's script: it replies `RC=10` with `idle_not_supported_over_arexx`. Scripts that wait for a song change use the hook (M4-AX-4-2) or poll `STATUS`.
- `BEGIN` / `END` work as on the socket: the lines between them are queued in that port's state and run as one transaction at `END` (design doc line 190).
- At exit: `RemPort`, then reply every queued message with `RC=20` and `port_closing`, then `DeleteMsgPort`. No message is left unreplied (an unreplied RexxMsg hangs the sender).
- Arguments with spaces: the line is parsed by the same codec as the socket, so `OPEN "DH0:Music/my song.mod"` works as on the socket.

## 8. Open questions for Johan

1. Port name `SELECTA`, then `SELECTA.2` and up for further instances. Trade-off: matches HippoPlayer and AmigaAMP practice; a mixed-case name such as `Selecta` would need quoting in scripts.
2. Socket replies with result lines end with a `.` line. Trade-off: existing clients that read one line still work for verbs without results; a JSON reply would be easier to parse on the Mac but awkward in ARexx.
3. Labels live in `commands.def` (one source of truth for every client). Trade-off: 103 labels to write once; keeping them in the desktop action table would leave ARexx and Amarchy without labels.
4. `IDLE` refused over ARexx; scripts use the hook or poll `STATUS`. Trade-off: no blocked senders; a script cannot wait for an event in one call.
5. No Selecta MCP server. On the Amiga, the amiga MCP's `amiga_rexx` drives the port directly. On the Mac, `selecta-cli send` over the control socket does the same from a shell. Trade-off: no new server to maintain; a Selecta MCP would give typed tools (play, status, wait for event) usable from any Claude session without a shell.
