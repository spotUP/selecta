# Selecta M4: Amiga UIs

Implements design doc `thoughts/shared/plans/2026-10-22-architecture-design.md` sections 7 (UI plugins, on-the-fly switching, machine-scaled layouts, Amiga OS integration F27, fullscreen visual mode F38, command palette F49, configurable columns F48), 6 (visualizers on bitmap surfaces, chip register panels), 9b (view styles; grid and cover flow on RTG), 10 (UI plugin descriptor tags, registry hiding by `NEEDS_RTG`), 12 (`sel_machine` scaling, no 68020/AGA ceiling), 13 (reachability), 14 (M4 row, UI part) and 1a (rows tagged M4 that a UI owns: chip register panels, OS file integration, signal path display and fullscreen visual mode F38). Decisions D-M4-2 and D-M4-3 add a UI plugin and a display-mode model the design doc does not have yet; the proposed design doc text is in "Proposed design doc text" below.

Out of this plan (still M4, separate plan): `LoadSeg` loader, UADE-native HW replayer plugin, ARexx port, hardware audio outputs F26. Open question Q11 confirms the split.

## 1. Goal and finish line

Goal: Selecta on the Amiga looks and works like a modern player (Spotify / Apple Music / foobar2000 class, section 9a references), not like a 1995 Amiga player, on every machine from an A1200 68020 AGA with fast RAM up to an RTG 060 / Vampire / PiStorm machine. One lead UI sets the bar; MUI, ReAction and GadTools are downscaled from it. Every Amiga UI opens using the full screen area by default and can switch to compact modes at run time. Playback never stops when the UI or the display mode changes.

Finish line: M4 (UI part) is done when every row of the phased checklist (section 6) is ticked with its reachability test green through `selecta --ui <id>` (host tests through the shell binary, Amiga tests on the rig through the 68k shell binary), the sentinel proves the new code ran, the stated number holds, the ratchet count of unimplemented M4 IDs is 0, and Johan has confirmed the manual checks (section 6, M4-P11-5). Command:

```
cmake --build build/host && nice -n 19 ctest --test-dir build/host -L m4 -j2 --output-on-failure
nice -n 19 ctest --test-dir build/host -R ratchet --output-on-failure
cmake --build build/amiga && nice -n 19 ctest --test-dir build/host -L rig-m4 -j1 --output-on-failure
```

Rig tests use the existing driver `tests/amiga/run_rig.cmake` (FS-UAE through `~/Code/UP-Term/vtcon/tools/rig`, `ami.py exec|put|get|key`); rig down prints `SKIPPED rig not running` and ctest reports Skipped, never Passed. Two rig configs are needed: `a1200-aga-020` (68020 14 MHz, 2 MB chip, 8 MB fast, AGA, OS 3.2) and `rtg-060` (68060, uaegfx RTG, OS 3.2, MUI installed). M4-P0-2 records them.

## 2. Shared UI model layer

Problem: four Amiga UIs (custom, MUI, ReAction, GadTools) plus the text UI would each re-implement the same view logic: transport state words, clock strings, panel labels, queue titles, key bindings, the command palette, layout decisions, compact modes. That is the duplication the single-source-of-truth rule forbids. The text UI already holds most of this logic, but privately.

Design: a new portable C99 library `src/uimodel/` (target `selecta_uimodel`, no OS calls, builds for host and 68k, links only `include/selecta/` and `src/engine/format.h`). Every UI plugin, the text UI included, consumes it. Toolkit plugins only translate its output into gadgets, MUI objects, ReAction classes or pixels.

### 2.2 What moves out of the text UI into `src/uimodel/` (lift, not copy)

The text UI keeps only terminal concerns (escape decoding `keys.c`, cell grid `grid.c`, sixel/kitty, size probe). The rest is lifted, renamed `sel_uim_*`, and the text UI becomes its first consumer:

- Key bindings: `txt_bindings_*` `plugins/ui/text/keybind.h:41-69` become `sel_uim_bindings_*` over neutral key codes; terminal sequences and Amiga RAWKEY both map to those codes in their UI.
- Command palette: `txt_palette_*` `palette.h:46-54` (fuzzy list over `COMMANDS` plus current binding).
- Command line model: `txt_cmdline_*` `cmdline.h:39-49` (history, completion; drawing stays per UI).
- Theme tokens: `txt_theme` `theme.h:26-44` become `sel_uim_theme` with roles extended for bitmap UIs (surface, surface raised, accent, text primary/secondary, divider, selection, focus ring, scope trace, VU low/mid/high), plus spacing and font-size roles (D8).
- Display strings: `tui_clock` `text_ui.c:595`, `tui_play_word` `text_ui.c:603`, `tui_stage_status` `text_ui.c:608`, `tui_queue_title` `text_ui.c:639`, `tui_label` `text_ui.c:713`.
- Panel content models (data only, no drawing): `tui_viz_panel` `text_ui.c:886`, `tui_pattern_panel` `text_ui.c:976`, `tui_phase_panel` `text_ui.c:847`, `tui_info` `text_ui.c:730` (which fields, which order, which labels).

Regression guard: every existing text UI screen golden (`tests/m1/*.cmake`, `tests/m12/reach.cmake`) stays byte-identical after the lift; that is the test for M4-P2-2.

### 2.3 New in `src/uimodel/`

- `sel_uim_frame`: built once per pump by `sel_uim_update(uim, sel_engine_state(e))`. Holds resolved strings (title, artist, format, clock, remaining, status line), transport flags (play state, can-prev, can-next, undo/redo depths from `QUEUE_HISTORY`), progress in Q16, the visible panel set, dirty bits per region so bitmap UIs redraw only what changed.
- Action table: one row per user action (`play_pause`, `next`, `view.style.grid`, `mode.mini`, ...) mapping to a protocol line or a pref write, with a label in full English words, icon id, menu path and default binding. Menus (MUI, ReAction, GadTools NewMenu), toolbar buttons, the palette and the help overlay are all generated from it. Parity rows of HippoPlayer and bbmp (section 6, M4-P2-5) are counted from this table.
- Layout tree: `sel_uim_layout(uim, w, h, &metrics, mode)` resolves a tree of regions (sidebar, content, now-playing panel, transport bar, status line, viz strip, overlays) with weights, minimum sizes and responsive breakpoints into rectangles. The custom UI and GadTools draw into those rectangles directly; MUI and ReAction translate the same tree into groups with weights and let their layout engines place gadgets, using the tree's minimums and breakpoints so all four UIs collapse panels in the same order.
- Display modes (section 3.4): the mode state machine, its pref key, its transitions and the layout tree per mode.
- Hit testing and focus order for bitmap UIs (custom, GadTools custom areas): `sel_uim_hit(x, y)` returns region and row; Tab order is the tree order.
- Effects budget: `sel_uim_budget(uim, frame_ms)` keeps a moving frame-time average and steps effect levels (animation, smooth scroll, viz rate, artwork scaling quality) down when frame time passes the budget, up when it has headroom, seeded from `SEL_MACHINE_CPU_SPEED` and tier. Same governor in every bitmap UI.

## 3. The lead modern UI

Revised after D-M4-5 and D-M4-6 (desktop UI plan `2026-10-24-desktop-ui.md`, M3d): the shared widget set, layout tree, tokens, rasterizer, `src/uimodel/` and the shell changes (`UI_SWITCH`, several UIs, mode pref host part) are built in M3d. M4 adds the Amiga backends (RTG, AGA) and OS integration. Text below that describes `plugins/ui/custom/` as a separate renderer is superseded by section 4.

### 3.1 Which plugin

The lead is a new plugin, `plugins/ui/custom/` (plugin id `custom`, UI name "Selecta"), a total-custom renderer with no toolkit limits (D-M4-2). It has two drawing backends behind one interface `cu_backend` (section 4): RTG (chunky truecolor) and AGA (planar, copper and blitter), plus a `mem` backend (chunky buffer in RAM) that runs on the host for tests. Recommended lead order (Q1): RTG backend first, because modern standards (truecolor, artwork, antialiased type, alpha) are reachable there without compromise; the AGA backend then downscales the same layout and views to 256 colours with hardware help. MUI, ReAction and GadTools follow (section 5).

### 3.2 Layout (full mode, default)

Modern three-column player layout, mouse first with full keyboard parity:

- Sidebar (left, collapsible): Home, Search, Library (sources: Local, Modland, HVSC, hippoplayer.se, Aminet ...), Playlists (folder tree, section 9c), Queue, Stats. Drag a song onto a playlist to add it.
- Content (centre): the current view in the chosen style (regular, tree, drilldown, grid, cover flow, compact; section 9b). Header with breadcrumbs, search field with typed filters (`format:`, `artist:`), style switcher, group-by menu, sort by clicking a column header. Composer and album pages, Home ("Jump back in", recently played, "New this week" from the Modland changelog).
- Now Playing panel (right, collapsible): artwork or generated art, title and composer, metadata panel (`sel_state.panel`: STIL note, release, year, genre, rating, play count), lyrics with the current line highlighted (`lyric_line`), up next (first queue rows), rating stars and like.
- Transport bar (bottom, always visible): previous, play/pause, next, shuffle, repeat, seek bar with elapsed/remaining and subsong selector, fade marker, volume, output name, "Signal Path" button (F38), mini scope.
- Tracker views (tab strip in the content area when a tracker song plays): Pattern (scroller, channel mute by clicking a column header), Instruments and Samples (click to play), Scopes (per voice), Spectrum, Note Dots, Phase, Chip Registers (SID/AY/YM/Paula via `SEL_RP_CHIP_REGS`), Module Info.
- Overlays: command palette (Ctrl-P equivalent on Amiga: Right Amiga + P), help overlay (Help key), context menus (right mouse button on the custom UI; Amiga menu bar convention is kept in toolkit UIs), toasts for errors (`SEL_EVT_ERROR`).
- Fullscreen visual mode (F38): the whole surface goes to one visualizer, chrome hidden, any key restores it.

Interaction standards taken from the references: hover and pressed states, a visible focus ring, smooth scrolling and kinetic wheel scrolling where the budget allows, type-to-find in lists, double-click plays, Return plays, Space toggles pause, undo/redo of queue edits, drag and drop between panels, tooltips with the key binding, every label in full English words.

### 3.3 Visualizers

Viz plugins render to `sel_surface` (section 6 of the design doc; the struct is added to `include/selecta/viz.h`) using the `VIZ_*` tags `tags.def:107-110`. M4 ships: per-voice scopes, VU, spectrum (integer bands; FFT where `FPU_SPEED` allows), pattern scroller, note dots, phase view, chip register panels, signal path diagram. Each declares `SEL_VIZ_SURFACES` (chunky8, chunky32, planar) and `SEL_VIZ_TIER`. The custom UI, MUI (custom area class), ReAction (space gadget) and GadTools (custom-drawn area) all host the same plugins; the text UI keeps its glyph tier and gains the bitmap path for sixel/kitty from the same plugins.

### 3.4 Display modes (D-M4-3): full screen default, compact modes, switching

Every Amiga UI (custom, MUI, ReAction, GadTools) supports the same mode set, defined once in `src/uimodel/`:

| Mode | Shape | Shows | Default size |
|------|-------|-------|--------------|
| Full (default) | custom UI: own screen; Workbench UIs: window covering the whole public screen area below the screen title bar | everything in 3.2 | screen width x (screen height - title bar) |
| Window | resizable window on the public screen, same layout collapsing by breakpoint (sidebar, then Now Playing panel fold into tabs) | content + transport, panels by width | half the screen width x two thirds of the height, remembered |
| Lowered screen (screen-owning UIs only) | own screen dragged down so Workbench shows above it | transport + one content area | bottom 40 percent of the display |
| Mini player | small window: artwork thumbnail, title, composer, transport, seek bar, mini scope | now playing only | about 320 x 64 pixels at the Workbench font size |
| Micro strip | one-line window (HippoPlayer "tiny" heritage): title, time, play/pause, next | title + time | one title-bar-high strip, 280 pixels wide |
| Iconified | Workbench AppIcon; drop a file on it = `QUEUE_ADD`; double-click restores the previous mode | nothing | AppIcon |

The custom UI draws Window, Mini player and Micro strip with the same renderer into a window on the public screen (RTG: chunky window bitmap; AGA: planar window bitmap with pens obtained by `ObtainBestPen` from the Workbench palette).

Switching, one mechanism for every UI and every client: the pref key `ui.<plugin>.mode` (values `full|window|lowered|mini|micro|icon`) written with `PREF_SET`; the UI reacts to `PREFS_CHANGED`. So ARexx, `selecta-cli`, the command palette, menus, keys and ToolTypes (`MODE=mini`, through the one parser of section 7 / F27) all switch modes the same way, and the last mode is remembered. Entry points in each UI: a "Display Mode" submenu in the View menu with all modes; the window zoom gadget toggles between Full and the last compact mode; key bindings (defaults, rebindable): Right Amiga + 1 to 5 for Full, Window, Mini player, Micro strip, Lowered screen, Right Amiga + I for Iconify; a mode button in the transport bar. A mode change keeps the view cursor, the selected song key and playback untouched (asserted, M4-P5-4).

## 4. Custom hardware UI: RTG and AGA variants

Revised after D-M4-5 and D-M4-6: the custom Amiga UI is the `src/gui/` library of M3d (widget set, `draw/` rasterizer, views, `mem` backend, fonts builder, theme presets in `src/gui/theme/`) running on two new backends. M4 owns only `amiga/backend_rtg.c`, `amiga/backend_aga.c`, `amiga/input.c` (IDCMP to neutral events), the Intuition window and screen handling, and the scale 1 atlases. The tree in 4.1 below shows the original layout; the `draw/`, `views/` and `backend_mem.c` entries now live under `src/gui/` and `plugins/ui/desktop/` per the M3d plan section 2.1.

### 4.1 Structure

```
plugins/ui/custom/
  custom_ui.c      plugin entry, open/close/wait/on_event, mode handling (consumes src/uimodel)
  views/*.c        home, browse/list styles, now playing, tracker tabs, overlays: draw into a cu_canvas
  draw/            portable 2D raster: rects, rounded rects, lines, gradients, alpha glyph text from atlases,
                   images (scaled, dithered), clipping, dirty-rectangle list
  backend_mem.c    host and test backend: chunky32 buffer, --frame-dump writes it, STAT_HASH hashes it
  amiga/backend_rtg.c   Picasso96 / CyberGraphX
  amiga/backend_aga.c   AGA planar, copper, blitter, sprites
  amiga/input.c    IDCMP to neutral key/mouse events
fonts/            build-time generated glyph atlases (1-bit and 4-bit alpha, several sizes) from one OFL font (Q13)
```

`cu_backend` ops: open(mode, w, h) / close, lock and unlock the back buffer, present (flip or blit dirty rects), palette set (AGA), copper program set (AGA), cursor set, capabilities (depth, chunky or planar, alpha cost). Views never call a backend directly; they draw into `cu_canvas`.

### 4.2 RTG variant (lead)

- Screen: Picasso96 (`p96OpenScreenTags`) or CyberGraphX (`OpenScreenTags` with a CGX mode id from `BestCModeIDTags`), 16, 24 or 32 bit; default mode = the Workbench mode id and size when Workbench is on an RTG screen, otherwise the largest RTG mode up to 1920 x 1080 (Q14). Implemented so far (`backend_rtg.c`): `OpenScreenTags` with `SA_DisplayID` of the Picasso96 mode found by size (not `p96OpenScreenTags`), minimum depth 16, canvas size from `LockPubScreen(NULL)` (I340); mode choice, fallback and low memory are M4-P5-7, M4-P5-8 and M4-P5-13. A screen narrower than 700 px uses the compact full-screen layout (M4-P5-6).
- Drawing: render into a back buffer in fast RAM with the portable rasterizer, then `WritePixelArray` / `p96WritePixelArray` the dirty rectangles; when the board allows `LockBitMapTags` and a second buffer, draw in place and flip with `ChangeScreenBuffer`. Full redraw only on mode change or resize.
- Effects at RTG tier: antialiased text, alpha shadows, artwork scaled with bilinear filtering, cover flow with perspective strips, animated transitions, 50 Hz scopes; the governor (2.3) steps them down on a slow CPU with a fast board.
- Vampire SAGA and PiStorm/Emu68 are handled as RTG through their P96 drivers (Q18).

### 4.3 AGA variant (maximum speed)

- Screen: an Intuition screen (so the OS stays alive and Amiga-M swaps to Workbench), 8 bitplanes, default mode = the Workbench display mode id (so a scandoubler or flicker fixer user gets their mode), fallback PAL 640 x 256 hires / NTSC 640 x 200, laced 640 x 512 offered in settings (Q14). Double-buffered with `AllocScreenBuffer` / `ChangeScreenBuffer`.
- Chipset use: blitter (`OwnBlitter` / `DisownBlitter`, `WaitBlit`) for fills, copies, scrolling list regions, glyph blits and line-mode scope traces; a user copper list (`UCopList`, `CINIT`/`CMOVE`/`CWAIT`) for per-region palette splits (sidebar, content, transport each get their own colour ramp, so 256 colours behave like more), vertical gradients for backgrounds and the VU, and a per-line colour change for spectrum bars; hardware sprites for the mouse pointer, the drag ghost and the playing-row marker; smooth list scrolling by moving the bitplane pointers inside a taller bitmap where the region is full width.
- Artwork on AGA: 64-colour sub-palette per visible artwork tile via copper split (cover flow row), ordered dither from the chunky source; HAM8 is not used (Q-free implementation choice: palette splits are cheaper to compose with UI chrome).
- Chip RAM budget: two 640 x 512 x 8 buffers = 640 KB of chip RAM, 640 x 256 = 320 KB; asserted at open against `SEL_MACHINE_CHIP_RAM` (M4-P6-1). Back buffers for views, glyph atlases, artwork and viz scratch live in fast RAM (baseline has fast RAM).

### 4.4 Coexistence with the OS (both variants)

- Screen ownership: system-friendly, never a full OS takeover (Q3). The UI owns an Intuition screen; no `LoadView(NULL)`, no `Forbid` around drawing; it takes the blitter only per batch with `OwnBlitter`. dos.library, bsdsocket.library, AHI and disk keep working, so library browsing, network sources and the cache are not lost in the custom UI.
- Input: a borderless backdrop window on the custom screen with IDCMP `RAWKEY`, `MOUSEBUTTONS`, `MOUSEMOVE`, `NEWSIZE`, `ACTIVEWINDOW`; RAWKEY goes through `MapRawKey` with the user keymap, then to neutral key codes and `sel_uim_bindings`. Its signal is the `ui_mask` of `sel_loop_init` (`src/core/amiga/loop.h:11`). No input.device handler (global hotkeys stay commodities-based, section 7).
- Audio: untouched. The engine owns Paula-direct or AHI output independently of any UI (design sections 3 and 5); the UI only renders `sel_state`. Asserted: a UI open, switch and close during playback causes zero output underruns (`sel_engine_stats`).
- Screen switching: Amiga-M / Amiga-N swap screens as usual; when the custom screen is not frontmost, drawing stops (no wasted CPU), viz taps keep filling.
- Public screen: the custom screen can be made public (`PUBSCREEN=Selecta`) so a requester (asl) opens on it.

### 4.5 CPU tiers

The 68020 AGA tier is one runtime tier of the same product, not a lite edition: views, features and the modern look are the same, only effects and frame rates scale (M4-P11-7). AGA and RTG differ in: colours (256 with copper splits versus 16 to 32 bit), text (1-bit atlas versus 4-bit alpha), shadows and bilinear artwork (RTG only), output of the frame (planar blitter versus `WritePixelArray` of dirty rectangles), and screen buffers (chip RAM versus fast RAM).

| Tier (from `sel_machine`) | Backend | Default effects | Targets (proposed, Q15) |
|---------------------------|---------|-----------------|-------------------------|
| 68020 14 MHz AGA, fast RAM | AGA | no animation, blitter scroll, scopes 25 Hz, 4 voices, integer spectrum 16 bands | input-to-redraw at most 40 ms; viz 25 frames per second; list scroll of 10 000 rows at 25 fps |
| 68030 / 68040 AGA | AGA | scopes 50 Hz, smooth scroll | viz 50 fps |
| 68060 AGA | AGA | all AGA effects, cover flow strips | viz 50 fps, transitions 25 fps |
| any CPU + RTG | RTG | antialiased text, alpha, artwork, governor-scaled animations | 68030+RTG: 25 fps transitions; 060/Vampire/PiStorm: 50 fps |

## 5. Downscale plan: MUI, ReAction, GadTools

Each is a separate UI plugin consuming `src/uimodel/` (same frame, action table, layout tree, display modes, viz plugins). Downscaling means: the same views and actions, mapped to the toolkit's widgets, with panels and effects removed where the toolkit cannot carry them, never with private logic.

| Aspect | MUI (`plugins/ui/mui/`) | ReAction (`plugins/ui/reaction/`) | GadTools (`plugins/ui/gadtools/`) |
|--------|-------------------------|-----------------------------------|----------------------------------|
| Baseline | MUI 3.8 API, MUI 5 features when present (Q8) | OS 3.2 ReAction classes (window, layout, listbrowser, chooser, clicktab, space, scroller) (Q9) | OS 3.0+ (Q10) |
| Layout | layout tree -> HGroup/VGroup with weights, Balance objects between panels | layout tree -> layout.gadget with weights | layout tree solved to rectangles by `sel_uim_layout`, gadgets placed manually, relayout on NEWSIZE |
| Lists | List/Listview (NList if Q8 allows) with columns from F48; tree via indented rows or Listtree | listbrowser.gadget: columns, hierarchy (tree style) natively | ListView: flat; tree and drilldown as indented rows and side-by-side ListViews |
| Grid / cover flow | RTG: custom area class drawing via the custom UI's `draw/` rasterizer; planar: hidden | same via space.gadget | hidden (registry `SEL_UI_VIEW_STYLES` declares regular, tree, drilldown, compact) |
| Viz | custom area class hosts viz plugins (chunky on RTG, planar on AGA) | space.gadget render hook | a custom-drawn area in the window RastPort, planar viz path |
| Now Playing panel | group with artwork (datatypes on RTG), metadata, lyrics | same | text metadata panel, no artwork on planar |
| Menus | from the action table (Menustrip) | from the action table | NewMenu from the action table |
| Display modes | all except Lowered screen | all except Lowered screen | all except Lowered screen |
| Theme | design tokens map to MUI pens/frames where MUI prefs allow, user MUI prefs win | tokens map to pens | tokens map to pens obtained with ObtainBestPen |

Order (Q16): MUI, then ReAction, then GadTools. Each reuses the bitmap pieces of the custom UI (`draw/`, viz plugins) for its custom areas, so the only new code per toolkit is the widget mapping.

## 6. Phased checklist

Revised after D-M4-5 and D-M4-6: 32 items moved to the M3d desktop UI plan (M4-P12-3 was split: the Amiga part stays here as an open item, the desktop part is DUI-P5-6). They keep their row here, marked `[>]` and `(moved to DUI-Px-y)`; the DUI row owns the test and the tick. Items marked `[>]` are not counted by the ratchet. Tests of the remaining M4 items reuse the M3d goldens (INDEX8 goldens are shared) and depend on M3d being landed.

IDs `M4-P<phase>-<item>`. Every test is a ctest entry with label `m4` (host) or `rig-m4` (rig, visible skip when the rig is down), driven through the shell `selecta --ui <id>` with `--exec` commands, a scripted key or IDCMP event file (`--keys`), and `--frame-dump` / `--screen-dump`. Sentinels are `UI_STAT_*` values printed by the shell at exit (`main.c:366`) plus new `UI_STAT_*` tags added to `tags.def` where named. ## 8. Open questions for Johan

1. Which UI leads. Recommended: the custom UI, RTG backend first, AGA second. Trade-off: RTG reaches modern standards without compromise but only owners of graphics cards see it first; AGA first serves the A1200 baseline earlier but sets a lower bar for the downscale.
2. One custom plugin with RTG and AGA backends, or two plugins. Recommended: one plugin, two backends. Trade-off: one layout and view code path and one test golden set; two plugins would let each diverge freely but duplicates every view.
3. OS coexistence. Recommended: system-friendly (own Intuition screen, `OwnBlitter` per batch, user copper list; OS, network, disk, AHI keep working). Trade-off: a full takeover (`LoadView(NULL)`, Forbid) is a few percent faster on a 68020 but kills library browsing, network sources and AHI while the UI shows.
4. Compact mode set. Recommended: Full, Window, Lowered screen (screen-owning UIs only), Mini player, Micro strip, Iconified. Trade-off: six modes cost one layout tree each (cheap in the shared layer) but six goldens per UI; fewer modes means less test surface but loses the HippoPlayer-sized strip users expect.
5. Mode switching mechanism. Recommended: the pref key `ui.<plugin>.mode` through `PREF_SET` / `PREFS_CHANGED`. Trade-off: no new verb and remembered across runs for free; a dedicated `UI_MODE` command would read better in ARexx scripts.
6. Full-screen default for Workbench window UIs. Recommended: a window covering the whole public screen area (below the title bar), zoom gadget to the last compact mode. Trade-off: keeps Workbench reachable and asl requesters work; an own cloned screen would look more like an app but hides Workbench and doubles chip RAM use on AGA.
7. Default mode keys. Recommended: Right Amiga + 1 to 5 and Right Amiga + I. Trade-off: easy to remember and free in Workbench convention; they clash with any user who bound those in Selecta key files (rebindable).
8. MUI baseline. Recommended: MUI 3.8 API, MUI 5 features when present, no third-party MCCs (NList, NListtree, TheBar). Trade-off: runs on every MUI install; NList would give better column lists with less code but adds install dependencies.
9. ReAction baseline. Recommended: OS 3.2 classes only. Trade-off: one tested class set; OS 3.1 users with ClassAct would be excluded from the ReAction UI (they still have MUI, GadTools and custom).
10. GadTools minimum OS. Recommended: OS 3.0. Trade-off: AGA pens and ObtainBestPen need 3.0; 2.0 support would mean a second pen path for a tiny user base.
11. Scope split. Recommended: this plan covers only the UI part of M4; `LoadSeg`, UADE-native, ARexx and F26 outputs get a separate M4 players plan. Trade-off: two plans to track; one combined plan would be very long and block UI work on the UpRough lift.
12. Generated 2D artwork in M4. Recommended: pull a deterministic 2D generator forward from M5 so grid and cover flow have pictures for songs without covers (nearly all modules). Trade-off: small extra scope; without it grid and cover flow show empty tiles until M5.
13. Font. Recommended: ship one OFL-licensed font as build-time glyph atlases (1-bit for AGA, 4-bit alpha for RTG) in the custom UI; toolkit UIs use the user's system fonts. Trade-off: identical, antialiased type on every machine; costs about 100 to 200 KB of fast RAM and ignores the user's font prefs in the custom UI.
14. Screen mode defaults. Recommended: the Workbench mode id and size (custom AGA and RTG), fallback 640 x 256 PAL on AGA, laced and larger modes in settings. Trade-off: respects scandoubler and flicker-fixer setups; a fixed 640 x 512 laced default would show more but flickers on a plain A1200.
15. Performance and size targets. Recommended: input-to-redraw at most 40 ms everywhere; viz 25 fps on 68020 AGA, 50 fps on 030+ AGA and 060 RTG; 10 000-row list scroll at 25 fps on 68020; 68k image budget to be set from the M4-P0 measurement. Trade-off: these numbers drive the AGA design (blitter scroll, copper splits); lower targets would allow a simpler renderer.
16. Downscale order. Recommended: MUI, ReAction, GadTools. Trade-off: MUI has the largest user base on RTG machines; GadTools first would cover OS 3.0 A1200 users earlier.
17. Several UIs attached at once on the Amiga in M4 (custom on screen plus text UI over serial). Recommended: yes, design section 7 already promises it and the test is cheap. Trade-off: two UIs share the 68020 budget; deferring it saves a test row.
18. Vampire SAGA. Recommended: treat as RTG through its P96 driver. Trade-off: no special code; a native SAGA backend could be faster for chunky drawing but is a third backend to maintain.
19. Lift of the text UI's private logic into `src/uimodel/` during M4. Recommended: yes, text UI becomes the first consumer, goldens unchanged. Trade-off: touches a finished UI (risk contained by byte-identical goldens); leaving it means every Amiga UI duplicates bindings, palette and strings, which the rules forbid.
20. Two-screen layout (Chipmachine style) in M4? Recommended: yes, as a layout preset (M4-P12-13), because the catalogue lists it and the layout tree makes it cheap. Trade-off: one more golden set and rig check.
21. Theme presets in M4 although design 1a row 92 puts theming D8 at M5? Recommended: ship the token loader plus the four Amiga presets and the Selecta default in M4 (M4-P12-8); the remaining bbmp themes and skins stay M5. Trade-off: theme file format is fixed one milestone earlier.
22. External lookup on the Amiga needs openurl.library. Recommended: use it when present, else show the URL in a requester. Trade-off: no browser launch on systems without openurl.
23. HippoPlayer parity document states 216 rows; its table body has 227. Recommended: correct the stated count in the document to the structure count. Trade-off: none; M4-P2-5 counts from the table either way.
24. Layout on screens below 700 px width (640x400, 680x270, AGA 640x256/200) (I343). Recommended: a compact full-screen layout: one content column with a bottom tab bar (Home, Browse, Now Playing, Queue) and a 24 px transport strip, no sidebar; Now Playing reachable as a full page. Trade-off: costs a second set of page layouts and goldens; the alternative, scaling the full layout down with a smaller font, makes text unreadable at 640 px and never fits 270 px of height.
25. Screen size fallback when the Workbench size has no Picasso96 mode (Replay 680x270). Recommended: open the largest listed mode that fits inside the wanted size and let the canvas follow it (M4-P5-7). Trade-off: a bordered smaller screen on a user's monitor; the alternative, opening the nearest larger mode, draws a canvas bigger than the screen again (I340) unless the layout scrolls.
26. Failure report when the UI cannot open a screen. Recommended: requester on Workbench start, stdout on CLI start, then keep the text UI. Trade-off: the text UI keeps playing but is not what was asked for; the alternative, exiting, is simpler and loses the session.
27. Compact layout minimum screen. Recommended: 320x200 stays unsupported by the custom UI (text UI only) and the smallest full layout is 640x200; GadTools and MUI cover smaller screens. Trade-off: PAL/NTSC lowres users get the text UI; supporting 320 px needs a third layout.
