# Amiga MUI UI plugin (`plugins/ui/mui/`)

## 1. Goal and finish line
`selecta --ui mui` opens a Magic User Interface window on the Amiga that carries every desktop-UI feature MUI can carry, with no private logic in the plugin. The plugin consumes `src/uimodel/` (frame, action table, layout, budget) and `src/gui/draw` (custom area only) and nothing else. Done means all items in section 5 tick, each with a ctest or a rig test that drives the top-level entry point.

Finish line, measurable:
1. `selecta --ui mui` on rig 2 (FS-UAE, uaegfx, UPTERM_RIG=2) opens a window the size of the public screen area; the sentinel stat `ui_open_mui=1` is read back (MUI-P1-5).
2. Menu item count in the MUI Menustrip equals the count of `sel_uim_action_at` rows with a non-empty `menu` path (MUI-P2-3).
3. Every desktop view in plan DUI-P4 that MUI can carry exists as a MUI group, fed from `sel_view_state` (P3, P4). Features MUI cannot carry are listed in section 3 with the reason, not silently dropped.
4. Smallest target 640x256 PAL hires is fully laid out in the compact one-column layout with the bottom icon row (Home, Library, Search, Queue, Now Playing) above the transport; 640x200 scrolls; below 640 px wide the plugin refuses and the shell keeps the text UI (Q24, Q26; MUI-P6-2, MUI-P6-3).
5. Display modes Full, Window, Mini player, Micro strip, Iconified switch through the pref `ui.mui.mode` with cursor, selection and playback kept; Lowered screen is not offered (MUI-P6-1).
6. User MUI preferences win over Selecta theme tokens (MUI-P7-1).

Commands (rig tests only on the caller's go-ahead; host tests are default):
```
cmake -S . -B build/host -G Ninja
nice -n 19 ctest --test-dir build/host -L mui -j2 --output-on-failure
nice -n 19 ctest --test-dir build/host -R ratchet
cmake --build build/host --target lint
ctest --test-dir build/m68k -L rig-m4-mui     # needs rig 2 running; prints SKIPPED when it is not
```
Rig facts: real RTG targets are FS-UAE rig 2 (`UPTERM_RIG=2`, uaegfx) and the Replay. The M4 plan name `rtg-060` is stale; this plan says "rig 2". Rig driver is `tests/amiga/run_rig.cmake` (wired at `tests/CMakeLists.txt:992`).

### 2.2 Shape
- `plugins/ui/mui/mui_ui.c`: descriptor and the SEL_UI_OPEN / SEL_UI_WAIT / SEL_UI_CLOSE / SEL_UI_STATS hooks. m68k-only target; the pure mapping code lives in `plugins/ui/mui/map/*.c` with no `<proto/muimaster.h>` include so host tests build it.
- Mapping functions (host-testable, pure): action table to Menustrip tree (`mui_menu_build`), layout regions to group weights (`mui_group_weights`), token to pen/frame (`mui_pen_for_token`), mode pref to window flags (`mui_mode_flags`), tier to offered style mask (`mui_style_mask`).
- Event loop: SEL_UI_WAIT calls `MUIM_Application_NewInput` with the engine wake signal OR-ed into the wait mask; returns 1 when a MUI input handled, 0 on timeout, -1 on quit (hook contract `ui.h:38`).
- Update path: `sel_uim_update` then `sel_uim_take_dirty`; each dirty bit maps to `set()` on one object (title, clock, progress, status word) or `MUIM_Redraw` on the list; no polling timer beyond the shell tick.
- Custom class `Selecta_Canvas` (subclass of Area via `MUI_CreateCustomClass`) owns one `sel_gui_canvas`, renders through `src/gui/draw`, blits to the RastPort with `WritePixelArray` (RTG) or `WriteChunkyPixels`. Used for grid, cover flow, viz and artwork only. All other widgets are native MUI so the user's MUI prefs apply.
- Lists: MUI `List`/`Listview` (3.8 baseline); NList and Listtree used only if present and Q8 allows (open question 1). Tree rows are indented rows (baseline), not Listtree.
- Baseline MUI 3.8 API; MUI 5 features probed with `MUIA_` availability at run time (Q8, accepted in 8a). No third-party MCC in the baseline.

### 2.3 Features MUI cannot carry (and why)
- Lowered screen mode: MUI windows open on a public screen and do not own one. Not offered; `ui.mui.mode=lowered` is refused (MUI-P6-1).
- Grid and cover flow, artwork, on planar (AGA) screens: needs chunky RTG pixels for the custom class; the planar path would need the custom UI's c2p. Style mask on planar = Regular, Tree, Drilldown, Compact (4); on RTG all 6 (MUI-P3-5).
- Tweens, fades, hover animation, shadows, gradients on native widgets: MUI draws its own frames; the governor `motion_allowed` is honoured only inside the custom area.
- Inter font atlas and token font sizes: MUI uses the user's MUI font prefs; the custom area uses the system font (MUI-P7-2).
- Software pointer, copper gradients, INDEX8 palette effects: screen-owning features of the custom UI.
- Window-less global hover repaint (DUI-P3-8): MUI repaints its own gadgets.
- Media keys, system clipboard beyond clipboard.device text: see MUI-P5-6 for what exists.
- Kiosk or screensaver full-screen takeover: needs a screen.

## 4. Testing
- 4.1 Shape: host tests (label `mui`) cover the pure mapping functions and run on every commit. Rig tests (label `rig-m4-mui`) cover the plugin on rig 2 and print `SKIPPED rig not running` when the rig is down.
- 4.2 Reachability, one test per feature: `rig-m4-mui-open` drives `selecta --ui mui` through the real shell, asserts the sentinel `ui_open_mui=1` plus the spec numbers. All other behaviour is tested where it lives (host mapping tests, the existing `src/uimodel` tests).
- 4.3 Instrument checks (Gate 3): the sentinel is checked on a known-live case (`--ui mui` run) and a known-dead case (`--ui text` run reads `ui_open_mui=0`).
- 4.4 Nothing in this plan runs on any Amiga or rig until the caller says so. Manual checks are listed under MUI-P7-6 and name the platform (Amiga).

## 6. Contradictions between code and the M4 plan
- C1: `src/uimodel/layout.c:15-33` uses breakpoints 1200/900/700 and returns the mini suggestion below 700. The M4 decisions (Q24, Q27: one-column compact layout at 640x256) have no compact breakpoint in code. Already tracked as DUI-P1-11 and M4-P5-6 / DUI-P4-20; MUI-P6-2 depends on it.
- C2: `include/selecta/uimodel.h:44` layout set is full, window, mini, visual. M4 3.4 modes lowered, micro, icon are not in uimodel; the mode pref is plugin-side for those.
- C3: M4-P8-2 says "offered count 6 on RTG, 4 on planar", but the offered set comes from the plugin's SEL_UI_VIEW_STYLES intersected with the machine (`engine.h:82`, `main.c:154`), so the plugin must compute the mask per tier (MUI-P3-5).
- C4: M4-P8-1 says window size = public screen area; Q25 (largest listed mode fallback) applies to screen-owning UIs only. MUI never picks a mode.
- C5: the M4 plan's `rtg-060` target is stale (rig 2 and the Replay).
- C6: no `ui_open_*` sentinel exists in the code yet; M4-P8-1 assumed it.

## 7. Open questions (not asked; recommended answer first)
1. NList and Listtree. Recommended: baseline only, plain List, no third-party MCC (Q8 stands). Trade-off: NList gives real columns and sort for little code but adds an install dependency; with it absent the code needs a fallback anyway.
2. Where the plugin is allowed to exist if MUI is absent. Recommended: hidden from the registry (M4-P11-2). Trade-off: no dead menu entry, but a user who installs MUI later must restart.
3. Custom area on planar screens. Recommended: no grid/cover flow/artwork on planar (4 styles). Trade-off: smaller test surface; AGA users on MUI lose cover views until a c2p path exists.
