Picked scope: composer pages and photos (photo doubles as SID cover), CSDb releases per song with
screenshots, tags / ratings / charts as browse and sort views, extra collections (CGSC, exotics,
public playlists). Chordian is OK with mirroring.

Ground rule: no new mirror. The DeepSID dump already lives in DEViLBOX
(`~/Code/DEViLBOX/server/data/deepsid.db`) and is served live by hippoplayer.se cygnus-server
(`cygnus-server/src/server/DeepsidRoutes.ts`, mounted at `https://hippoplayer.se/cygnus/api/deepsid/*`).
Selecta talks only to hippoplayer.se. All new data work happens on that server.

Ledger wording to honour: rows must "mirror everything DeepSID's db holds (stats, links, profiles),
not a subset". Section 1 is the checklist for that.

## 2. Selecta data model

### 2.1 The key is the HVSC path

DeepSID's `hash` is not a full-file md5 (Commando: DeepSID `7fe08f19...`, full-file md5
`6d019ecb...` which is what Selecta's `songs.md5` and HVSC Songlengths.md5 hold). So the join is on
the HVSC path, never on md5.

Every SID song in Selecta resolves to one canonical key `hvsc:<path relative to C64Music/>`:

1. Song from the hvsc source: key is already `hvsc:<path>`.
2. Song from modland `pub/modules/HVSC/<p>` or the HVSC URL: `sel_stil_owner_key`
   (`src/library/db/user.c:136`) already maps it to `hvsc:<p>`. Reuse it, do not write a second mapper.
3. Local file, DLNA, SMB or any other source: look up its full-file md5 in the hvsc source rows
   (61148 rows carry md5 from Songlengths.md5) and take that row's path.
4. Fallback when md5 misses (edited rip, CGSC, SID Happens): path-suffix match on
   `<MUSICIANS|DEMOS|GAMES>/.../<file>.sid`, and for CGSC a `cgsc:` key with the same rules.
5. No match: the song gets no DeepSID data, and the miss is cached (below).

One helper, `sel_deepsid_key(lib, source, path, md5) -> "hvsc:<p>" | "cgsc:<p>" | NULL`, wraps
steps 1-5. It lives in `src/library/db/` next to `sel_stil_owner_key`.

### 2.2 Local cache: fetch on demand, never the whole db

The client never mirrors deepsid.db (51 MB sqlite, too big for a 16 MB Amiga and pointless on Mac).
It fetches lazily, on the job thread (RULES 1a), when a song or a composer is shown:

- Per song: `GET <base>/cygnus/api/deepsid/file-by-path?path=<p>&full=1` (full=1 adds the missing
  fields from section 1, see S2).
- Per composer: `GET <base>/cygnus/api/deepsid/composer?path=<folder>`.
- Browse views (tags, charts, collections, compos, players): paged list routes, not cached
  beyond the session except the first page (for an instant open).

Storage (recommended, D3): artwork rows keyed by the canonical key, the same table and pattern as
the Demozoo cover cache (`sel_art_dz_id(key)` in `src/library/db/art_scrape.c`), new kinds:

| kind | key | value |
|---|---|---|
| `ds_file` | `hvsc:<p>` | server JSON for the file (tags, STIL, player, CSDb ids, GB64, placings) |
| `ds_composer` | `hvsc:<folder>` | server JSON for the composer (bio, links, photo name) |
| `ds_miss` | `hvsc:<p>` | timestamp; no DeepSID record, retry after 30 days |
| `ds_csdb` | `hvsc:<p>` | CSDb releases + screenshot URLs from S4 |

Each row carries the server's `hvscVersion`; a newer server version invalidates rows lazily.
Tags are also written as stickers on the key so the existing sticker search and sort work
unchanged (the same way STIL is stored, `user.c`). User verdicts stay in stickers, server data in
artwork rows: the I1419 rule.

### 2.3 Covers

Composer photo becomes the SID song's cover when nothing better exists. Order in `dz_step`
(`art_scrape.c`): folder art, then cover_url, then DeepSID composer photo (new), then the Demozoo
lookup. The photo is stored with the existing `sel_library_cover_url_put(lib, source, path, url)`
(line 453), so `url_art()` fetches it under its 2 MB cap and the rest of the cover pipeline
(thumbnails, Amiga resize, text UI exemption RULES 9) needs no change. Placeholder
`composer.png` is never stored as a cover. Same prefs as Demozoo: `art.demozoo` and
`SELECTA_ART_SCRAPE=off` switch it off.

### 3.3 Browse tiles (Browse page, `SEL_ROUTE_BROWSE_TILE`)

- Tags: list of tags grouped by type with song counts; open one for its songs (sortable by

- Charts: top rated, most played, newest uploads (SID Happens). Source per D1.
- Collections: HVSC, CGSC, SID Happens, Exotic (Public Playlists dropped 2026-11-17: the DeepSID author did not clear them). Each opens its folder tree

Sort and filter: tags become a filter chip in the existing song list sort / filter bar, so any
song list (not only DeepSID views) can filter by DeepSID tag.

### 3.4 Home

the shelf mechanism; off when the DeepSID pref is off.

## 5. Amiga limits (68020, 16-256 MB, AmiSSL)

- Memory: per-song and per-composer JSON only, under 8 KB each; list pages capped at 50 rows on
  machines under 32 MB. No deepsid.db on the Amiga, ever.
- Images: S7 resized JPEG (160 px for lists, 320 px for the composer header). Screenshots only
  on demand, one at a time, freed when the page closes. Over-RAM: hide thumbnails, keep text.
- Transport: AmiSSL is present (`src/library/net/tls_amissl.c`, `tls_gate.c`). Without AmiSSL the
  client uses the S8 plain-http path; with it, https. Same base helper as the mirror client
  (`sel_devilbox_base()`), no second base URL.
- CPU: JSON parse on the job thread only; the 68020 must never parse on the screen thread
  (RULES 1a). Tag stickers are written in one transaction per song.
- Covers: composer photo goes through the existing Amiga cover resize; nothing new.
- Rig check once per batch at the end (memory "Rig test at end"). Use a HVSC SID with full
  DeepSID data, e.g. `MUSICIANS/H/Hubbard_Rob/Commando.sid`, not the usual mod test song.

## 7. Decisions for Johan

- D1. Source for ratings, charts and public playlists. The public dump has 5 rating rows and an
  empty symlists table, so DeepSID charts and playlist contents cannot be served from it.
  Recommended: ask Chordian for a ratings aggregate (per file: count, average) and a symlists
  export; meanwhile charts come from hippoplayer.se's own Selecta ratings and play counts.
  Trade-off: interim charts start nearly empty and reflect Selecta users, not DeepSID's community.
  Other option: scrape DeepSID's live API for charts (fresh, but load on Chordian's server and
  breaks when his API changes).
- D2. CSDb screenshots. Recommended: server crawl by csdbid, paced 1 s, cached for all users.
  Trade-off: 60550 files take about 17 hours for the first crawl, but data stays current.
  Other option: import DeepSID_Images_CSDb.zip (instant, frozen at May 2024, larger disk).
- D3. Client cache storage. Recommended: artwork rows, no migration. Trade-off: JSON blobs are
  not queryable by SQL; tags still are, through stickers. Other option: a V24 table (after
  I1432's V23), queryable but one more migration on every platform.
- D4. Amiga transport. Recommended: plain-http on hippoplayer.se (S8, as I1228) with resized
  images; AmiSSL when installed. Trade-off: plain http is unencrypted, acceptable for public
  read-only data. Other option: AmiSSL required (fewer server rows, excludes machines without it).
- D5. Composer photo as SID cover. Recommended: yes, after folder art and cover_url, before
  Demozoo. Trade-off: every song by one composer shows the same cover. Other option: photo only
  on the composer page, Demozoo first for covers.
- D6. Dump refresh cadence. Recommended: manual script run per HVSC release (about twice a year).
  Trade-off: CSDb links and new uploads lag until a refresh. Other option: monthly timer (needs a
  stable dump URL from Chordian).
- D7. Tag writes from Selecta. Recommended: read only. Trade-off: users cannot fix tags from
  Selecta. Other option: write-back to DeepSID (needs Chordian's consent and accounts; out of
  scope for the mirror).
