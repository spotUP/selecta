# I1019 One search over all sources (design)

Johan 2026-11-03 (not re-litigated): no scope chips. One query searches the library and every enabled searchable
built-in source, whether or not it sits in the sidebar. Library groups first, then one "From <source>" section per
source, filling in after the library ones. Type chips All, Songs, Albums, Artists stay and filter both. Spotify is the
reference.

## 0. Core decision: the engine owns the fan-out and the merged result view

RULES.md 1 (engine is the single source of truth, no derived state in a UI) decides the shape. Today the desktop
holds the online hits itself (`on_row[120]`, desktop_ui.c:374-377, filled by `online_event` desktop_ui.c:8681-8704)
and decides which sources exist (`online_scope_count` desktop_ui.c:8621). The MUI has neither. With all sources searched
at once, keeping hits in the UI would mean N copies of hit storage, a UI-side keyboard model across two lists and a
second implementation in MUI.

Instead:
- `SOURCE_SEARCH * "<query>"` (the existing command, commands.def:75; source `*` = all) makes the engine search every
  source with a search hook that is enabled (`SEL_PREF_LIBRARY_SOURCES_OFF`, the rule at engine.c:5520 and
  `SRC_SEARCHABLE` tags.def:399). The single-source form stays for the CLI and remote.
- The engine appends one section per source to the SEL_VIEW_SEARCH view it already builds in `search_reload`
  (engine.c:6073-6127, today "H Songs (n)", "H Albums (n)", "H Artists (n)"): `H From <name> (n)` then `S <source:path>\t<title>  <artist>`
  rows. So the desktop list loop (desktop_ui.c:9087-9134), the engine cursor, VIEW_ACTIVATE (engine.c:9554, plays a
  song row by key) and the MUI list (mui_ui.c:2085, mui_views.c:59) all show the online hits with no second path.
- The UI-side online model (`on_row`, `on_state`, `online_*` functions, desktop_ui.c:8593-8815) is deleted.

## 1. SOURCE_SEARCH fan-out

Today (single source):
- UI start: `desk_search_fire` desktop_ui.c:8817 -> `online_fire` desktop_ui.c:8664 sends `SOURCE_SEARCH <scope> "<q>"`
  through `desk_send` (queues only, I829 finding).
- Engine: `cmd_SOURCE_SEARCH` engine.c:7577 -> `search_start` engine.c:7550 -> `sel_library_task_start(search_task)`;
  the task runs `sel_source_search` (source.c:256) on the library job thread (one task slot shared with scan and sync,
  engine.c:593-600). A request while busy waits in one slot `search_wait_*`; a newer one replaces it (engine.c:7586-7588).
  A running search is never cancelled by a newer query.
- Results: `search_collect` engine.c:7592 (pump thread) emits one LIBRARY_RESULT per hit plus `search_done`, and writes
  the pref `search.last_source` (engine.c:7621).

New (all sources):
- Engine state replaces the single `search_hit[SEL_SEARCH_HITS]` + `search_source` (engine.c:584-592) with a fixed
  bucket array, allocated at start (RULES 4: no allocation after start): `search_bucket[SEL_SEARCH_SOURCES_MAX]`,
  each `{ id, name, state (queued, running, done, failed), n, hits[SEL_SEARCH_HITS_PER_SOURCE] }`, plus `search_gen`
  (uint32, bumped per query) and `search_query`. Size: SEL_SEARCH_SOURCES_MAX = number of registered sources with a
  search hook (count at register time, `sel_source_register_builtin`), SEL_SEARCH_HITS_PER_SOURCE = 40. Measure the
  struct size on the 68k build and write it in the row; budget stays under today's 120-hit array times 2.
- `cmd_SOURCE_SEARCH` with `*`: bump `search_gen`, fill the buckets in source registry order (the sidebar order) with
  every enabled searchable source as `queued`, clear hits, `search_reload` (sections show "Searching"). If a search task
  runs, `sel_library_task_cancel_request` (db.h:546, non-blocking, I782); otherwise start the first queued bucket.
- One library task per source, sequential (reuses `search_start`/`search_task`/`search_collect` as they are, one bucket
  at a time). Parallel per-source threads are rejected: one task slot is shared with scan/sync, and the Amiga has no job
  thread (engine.c:46-50, job.c header). Latency is the sum of the sources; each section appears as soon as its own
  source answers, which is the Spotify feel Johan asked for.
- `search_collect`: if the finished task's generation != `search_gen`, drop its hits silently (no events, no view
  change) and start the first queued bucket of the current generation. Else mark the bucket done/failed, `search_reload`,
  emit the existing LIBRARY_RESULT rows (kept for remote/CLI clients, tagged SRC_KEY per source), and start the next
  queued bucket. Scan and sync still take turns through `scan_start_next`/`sync_start_next` (engine.c:7626-7628).
- Drop the `search.last_source` pref write (engine.c:7621-7624) together with the UI restore (section 4).
- Empty query (`SOURCE_SEARCH * ""`): bump generation, cancel request, clear buckets, no sections.

How results land in the UI: the view refresh after `search_reload` bumps the view version; the desktop draws on the
state change as it does for library results today. No UI event handler for hits remains (`online_event` deleted).

## 2. Debounce, cancel, I829, I832, quit

- Debounce stays the one 250 ms timer (SEARCH_DEBOUNCE_MS desktop_ui.c:8590, `desk_search_tick` 8854). On fire,
  `desk_search_fire` sends the library lines (desktop_ui.c:8834-8840) and then `SOURCE_SEARCH * "<q>"` in the same burst.
  The line is built by a shared uimodel helper next to `sel_uim_search_line` (used by desktop 8834 and MUI
  `mui_search_lines` mui_views.c:110), so both UIs send the identical fan-out line.
- Cancel on a new query is the generation bump plus `sel_library_task_cancel_request`. I832's fix makes the net poll
  watch `task_cancel` while a task runs (job.c `job_main`, db_internal.h:86), so the stale network wait ends at the next
  poll slice (~50 ms) instead of after the answer. Stale hits never reach the view (generation check).
- I829 guard: nothing new runs on the UI thread. `desk_send` only queues; the engine command thread only fills buckets
  and posts the request; the network runs on the job thread. The dui test keeps the frame-count assertion during the
  fixture's 4 s first-byte delay.
- Quit: `sel_engine_destroy` engine.c:9887-9889 already cancels a running search task with the blocking
  `sel_library_task_cancel` (I832 makes that fast). Add before it: clear the bucket queue (all queued -> none) so no
  later collect could start another source. Destroy never calls `search_collect`, so one cancel ends all in-flight
  searches: there is at most one running task, the rest are only queued entries.

## 3. Layout, states, hover, keyboard, history

Layout (desktop draw_search desktop_ui.c:9011):
- Field, then the four type chips at their fixed rects (`search_facet_rect` desktop_ui.c:8860), always drawn and
  active. No other chips. The facet loop condition `d->scope[0] == '\0'` (9030) goes.
- Body: library groups (Songs, Albums, Artists, as now), then per source `From <name> (n)` heading (same 18 px heading
  look, desktop_ui.c:9099) and 32 px song rows drawn by the same row loop (9100-9131): title in text ink, artist and
  format after it as today's online sub-line (desktop_ui.c:8776 format). One row height for all sections, so the
  48 px online layout (8739-8781) and its scroll walk (search_content_h 8985-8987) are deleted.
- Type chips: online hits are songs. All shows every section; Songs shows library Songs and every From section;
  Albums and Artists hide the From sections. Group detection moves into one shared helper
  `sel_uim_search_group(const char* heading)` (uimodel, next to `sel_uim_search_facets` uimodel.h:174) returning
  1 songs, 2 albums, 3 artists, 4 online. It replaces the three copies of the `strncmp(t, "Songs", 5)` test
  (desktop_ui.c:8995, 9061, 9093) and the facet heading match in `mui_search_facet_line` (mui_tiles.c:145-153).
- Per-source states (rows the engine puts under each From heading, a keyless note row like the count line):
  queued or running: "Searching"; failed: "Could not reach <name>"; done with 0 hits: "No results". The library
  part keeps "Type to search songs, albums and artists" (desktop_ui.c:9135) for an empty query. A From section never
  shows before the library groups, even when its answer comes first: it is appended after them in `search_reload`.

Hover: From rows are song rows in the shared loop, so they take `list_row_fill` (desktop_ui.c:1020) and
`song_row_reg` (desktop_ui.c:9124), which registers the hover box; a pointer move then repaints through
`desk_hover_move` (desktop_ui.c:13418). This closes the online part of I1015 and I1011. Right-click goes through the
song-row menu, so the special online right-click branch (desktop_ui.c:3410-3420) is deleted; check that the song menu
on a `source:path` key pins as `search_pin` (engine.c:2857) does today.

Keyboard: one engine cursor over the one view. Up/Down walk library rows, then the From rows in section order; Enter
on a From row goes through the existing Search key branch (desktop_ui.c:12906-12918) -> `desk_play_path(sr->key)`
with the `source:path` key, the same call `online_click` made (8808). No new key code.

Back/Forward (I1012): `desk_rt_leave` (desktop_ui.c:9846-9851) keeps query, facet and scroll; the scope argument goes
(`sel_route_hist_keep` keeps "" in `sub`, or the field is removed from the route entry if nothing else uses it).
`desk_rt_search_restore` (9855-9868) loses its scope branch and the PREF_SET. Restore re-fires the query, so the
online sections fetch again; the scroll restore (`search_restore`, draw_search 9037-9041) already waits until the
content is tall enough, which now includes late From sections. The reopened I1012 key bug (focused field eats
Alt+Left/Right) stays in I1012; this design does not fix it.

## 5. Amiga MUI 3.8

What comes for free: MUI renders the SEL_VIEW_SEARCH list (mui_ui.c:2085), so the From sections, their state rows and
Enter-to-play appear with no MUI class work; the type chips (mui_ui.c:1551-1560) jump to headings through
`mui_search_facet_line`, which moves to the shared group helper. MUI keeps its own hover (I1015 exemption stands).

What differs: the Amiga build has no library job thread (engine.c:46-50, job.c header: builds without threads run
tasks inline in `sel_library_task_start`). A fan-out there runs each source's network search inline on the engine
command path, one after another. Per keystroke this would stall MUI for the sum of N network round trips.
Recommended: on the Amiga the MUI sends `SOURCE_SEARCH *` only when the String gadget is acknowledged (Return), not per
change; library search stays per change. The engine stays the same. This is a platform scaling decision under RULES 4
(sel_machine has no job thread), not a cut. Rig check: Return on a query shows "From Modules.pl (n)" in the MUI list on
rig 2 (fs-uae, --ram 256, real network). Johan confirms (Decisions).

## 6. Test plan

Reachability (one, through the real entry point): new `tests/dui/search_all.cmake` (or rework of
`tests/dui/search_online.cmake`, which already has the net fixture with a 4 s first-byte delay, tests/net/modulespl.cmake).
Start the desktop UI, open Search through the sidebar door, type the query through key events into the field (the real
debounce path), then assert from the dump:
- sentinel: engine `sel_source_search_runs()` (source.c:252) delta == number of enabled searchable sources, counted from
  the SOURCES rows the engine sent (SRC_SEARCHABLE and SRC_ENABLED), not hard-coded;
- order: library heading "Songs (n)" above "From Modules.pl (k)", k == the fixture's hit count;
- no scope chip rects in the dump; the four facet rects equal before and after the results;
- during the 4 s delay the From section shows "Searching" and the frame counter advances (I829 guard);
- hover through the real repaint path: pointer move onto a From row via the event path (desk_hover_move changed=1,
  not the per-frame redraw) and the row fill becomes SURFACE_HOVER;
- Albums chip hides the From section, Songs shows it.

Where the rest lives:
- Engine (tests/engine, a new `source_search_all_test.c` beside the existing SOURCE_SEARCH users): disabled source
  skipped; a second query mid-search cancels (cancel_request seen) and stale hits never enter the view; buckets fill in
  registry order; failed source gives the "Could not reach" row; empty query clears; no `search.last_source` written.
- Quit: `tests/dui/search_online_quit.cmake` (I832) keeps its bound (quit during the delay well under 4 s), now typing a
  query with no scope chip. Revert proof: drop the queue clear and the cancel, it must go red.
- Back/Forward: the I1012 step in `tests/dui/search.cmake` asserts query, facet and scroll with From sections present.
- Shared helper `sel_uim_search_group`: uimodel unit test (four heading kinds).
- Amiga: rig check as in section 5.

## Decisions for Johan

1. Modules.pl Radio entry: today it sits on top of the Modules.pl scope (desktop_ui.c:8607, 8756-8762) and I1014 wanted
   it only on an empty query. Without scopes Search has no place for it. Recommended: show it on the Modules.pl source
   page (the sidebar row / Browse tile target, desktop_ui.c:8948-8954). Alternative: a first row of the From Modules.pl
   section when the query matches "radio".
2. Amiga: online sections fire on Return only (no job thread, inline network per source), library search stays live.
3. Default picked, veto if wrong: Albums and Artists chips hide the From sections (sources return songs only).
