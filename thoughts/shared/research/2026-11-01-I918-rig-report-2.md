## Cause: zoomed PatternScope characters
plugins/viz/sidregs/sidregs.c:98-99: `scale = g->rh / 7 > 1 ? g->rh / 7 : 1`, passed to `vs_text` (plugins/shared/viz/glyphs.h:52-56, glyph H=6, advance 5). Scale depends only on row height (rh = surface h / ROWS=8, lines 7-8, 164-176), with no cap by column width (cw = w / COLS=40) or UI font. Design doc section 2 assumed 4 stacked panes (rh ~16, scale 2); the I918 single pane gives ~420x180, rh ~22, scale 3. Pixel aspect: `vs_text` scales every glyph pixel `scale x scale` (square). grep for aspect/Resolution in plugins/viz, plugins/shared/viz and mui_vizarea_class.c finds nothing, so the scope ignores the tall pixels of 640x256 hires: a square-scaled glyph looks tall and narrow there. Not fixed: the cap value and aspect policy are a design choice (suggest cap by width: `6*cw/(4*VS_GLYPH_ADVANCE)`, and x scale = 2x y scale... decide). On planar/AGA MUI the viz area is blank by design (mui_vizarea_class.c viza_step returns when !rtg), so it can only show on RTG MUI (unverified).

## Cause: "MUI window could not open ... (the layout needs 670x619 px ...)" (feeds I949)
Johan's text: "Selecta: the MUI window could not open. Using the text UI. (the layout needs 670x619 px, more than the screen shows)". Source: mui_ui.c:3080 (the why text), fallback via mui_report(MUI_FAIL_NO_WINDOW).
- Height model is wrong: `mui_layout_min_height()` (map/mui_screen.c:22-29) returns 304 px (rig log: "layout needs 304 px high, Workbench is 256"), built from topaz-8 constants (mui_map.h:389) and the mini layout. The real MUI minimum is far larger. So mui_screen_plan (mui_screen.c:30-48) believes a laced 640x512 screen is enough, but the real minimum is 619 high and 670 wide. Even the laced screen (640x512) cannot hold it; and 670 > 640 wide.
- Rig log, first run, own screen opened laced 640x512 depth 4: `window minimum 670x619, screen 640x512, open 0`.
- Second run (own screen did not open because the first instance still held the SELECTA public screen, so it used the 640x256 Workbench): `window minimum 530x459, screen 640x256, open 0`. The min differs between the two runs (screen font/metrics differ), unexplained.
