## Step 4: shared key defect (CONFIRMED)

- Three covers in one shelf row produce ONE cover key (110/72, pen 254).
- Cause: `copper_gradient` in src/gui/draw/gui_draw.c matches an existing key on `ry`/`rh` only (lines ~1111-1114); on a match the new colours `a`/`b` are dropped, the rows are painted with the first key's pen. Covers of different songs have different genart colours (the old allocator, keyed on ry/rh/a/b, made 3 keys for these covers per the I628 note), so tiles 2 and 3 show tile 1's colours. Not seen on screen (no screenshot taken: image reads are blocked in this session), but the code path and the key count agree.
- Fix direction: one pen cannot hold two colours on the same rows, so covers sharing rows need either distinct pens that each only cover their own columns (copper changes are per-row, not per-column: impossible), or the extra covers must dither. The correct behaviour is: match on (ry, rh, a, b); a second colour on the same rows takes the dither path (counted as miss), and the shelf row shows one copper cover plus dithered ones. Decision for Johan/design: accept that only one cover per shelf row can be copper.
