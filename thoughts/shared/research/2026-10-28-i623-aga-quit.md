# I623: AGA Selecta ignores Ctrl-C

## Measurements (FS-UAE rig 3, 68060, bsdsocket.library 4.1)

1. Full AGA Selecta with no network traffic, playing virgill-that_meme_again.mod
   (`--exec "OPEN ..." --exec PLAY`): `Break <pid> C` ended it within 10 s with
   `desktop_ui closed frames=25 title=meme.mod clock=00:24 status=Playing`, rc 0.
   So the UI poll (`plugins/ui/desktop/amiga/backend_aga.c` `desk_aga_poll`, CTRL_C check at
   line ~389/390) and the shutdown with audio both work. The hang needs network activity.
2. Probe (bsdsocket only): a nonblocking connect to 10.255.255.1, then WaitSelect with
   CTRL_C pending: `WaitSelect=-1 errno=4 (EINTR) ctrl_c_before=1 ctrl_c_after=0`.
   bsdsocket's default break mask is SIGBREAKF_CTRL_C; the stack aborts the wait and
   CLEARS the signal bit.

## Cause

`src/core/amiga/net.c` `wait_sock` (WaitSelect) and the resolver run on Selecta's main task
(jobs run inline on Amiga: art, DEViLBOX loudness/lyrics/genre, source sync, see the
`sel_net_set_cancel` comment). A Ctrl-C that lands while any of these waits is swallowed by
bsdsocket: the call fails as a plain connect/IO error and the bit is gone, so `desk_aga_poll`
never sees the break. With sync and fetch traffic running often (the I582 log shows every
source syncing), most breaks land in a network wait.

## Fix

`net.c` `keep_break()`: after a socket call fails with EINTR, raise SIGBREAKF_CTRL_C again on
the task. The call still fails fast (EINTR), and the next UI poll returns DESK_AGA_QUIT.
Called after WaitSelect failure, after a failed resolve and after a non-EINPROGRESS connect.
Rejected: setting SBTC_BREAKMASK to 0. It keeps the bit, but every network wait would then
run to its timeout (up to 10 s or more) before the UI could quit.

## Regression test

`rig-i623-net-break` (tests/CMakeLists.txt, TAG I623NET in tests/amiga/run_rig.cmake) runs
`selecta-net-break` (tests/amiga/net_break.c, built in the Amiga tree) on the rig:
- case pending: break set before `sel_net_open` to 10.255.255.1
- case wait: `Break <pid> C` sent 3 s into the 10 s connect wait
Both must end the wait at once and print `ctrl_c_kept=1`.

Rig 3 results:
- with fix: `mode=pending rc=-3 ms=0 ctrl_c_kept=1`, `mode=wait rc=-3 ms=3300 ctrl_c_kept=1`, Passed.
- fix reverted: `mode=wait rc=-3 ms=3320 ctrl_c_kept=0`, RED. The pending case still passed
  when reverted (the stack seems to leave a bit that was set before the call alone at
  connect time); the wait case is the one that guards the fix.

Run: `UPTERM_RIG=<n> nice -n 19 ctest --test-dir build/host -R rig-i623-net-break`
(needs build/amiga with target selecta-net-break).

## Unverified

- Full AGA Selecta quitting on Break while a real network job waits: not driven end to end.
  The probe proves the layer; which job Johan's break hit on rig 2 is inferred, not traced.
- Other blocking bsdsocket calls (send/recv are nonblocking and go through wait_sock;
  gethostbyname is covered by keep_break on failure).

## Part 2 open: reachable quit control

The desktop UI has no quit action of its own: `desktop_ui.c` only reacts to DESK_SDL_QUIT
(lines ~9252 and ~9378), which comes from the window close on SDL and from CTRL_C on AGA.
On the SA_Exclusive AGA screen there is no close gadget, so a user can only quit with Break
from another shell. A quit entry needs a place in the existing menu or key map; not done.
