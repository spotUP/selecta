# bbmp architecture

Source: /private/tmp/claude-501/-Users-spot-Code-MusicPlayer/1d27ca56-a355-4a5d-b8ae-938ae20e489e/scratchpad/ext/bbmp (read only, nothing run). Paths below are relative to it.

## Summary
- Catalog = one SQLite file per collection (`files` table, FTS5 search), attached together and exposed through TEMP views. Per song there is NO genre or chip column: "format" is the browse category AND the replayer selector; chips live in a side table.
- Replayers = out-of-process helpers, one per engine family, wrapped in bwrap / Landlock / Seatbelt. Two protocols: one-shot argv + JSON line + raw PCM (C/C++ helpers), and a command/response protocol (Python libs run in a sandboxed Python child).
- The helper contract for C++ engines (`csrc/amiga/engine.h`) is only two methods: `open()` and `render()`; engines self-register.
- Audio: fixed 48 kHz s16 stereo from every backend, no resampler, mixing is done by the backends. Output = PulseAudio simple API (Linux) or a tiny miniaudio ring-buffer lib (macOS).
- TUI: Textual, player runs in its own thread, UI POLLS a copied `Status` dataclass at 12 Hz. Not event-driven.
- Format to replayer: by catalog format NAME (dict generated from a census of Modland), extension only for local files. No magic sniffing for selection (some helpers sniff internally; unconfirmed).

## 1. Catalog / browse model
- Collections are `Collection` subclasses registered in `src/bbmp/collection/__init__.py` (docs/collections.md:19-23). Six: modland.py, hvsc.py (hosted by Modland, `hosted_by`), asma.py, sndh.py, zxart.py, keygenmusic.py.
- Per-song schema `Entry` (src/bbmp/collection/base.py:30-40): `path, format, artist, album, name, hidden, md5, size`. No genre. `Listing` (base.py:43-62) adds side data: `lengths` (per-subsong durations), `changes` (day, kind, path), `dated`, `chips` (path, chip), `notes` (HVSC STIL text).
- Format/artist/album are derived from the PATH LAYOUT by each collection's parser: Modland `parse_path` -> `_entry` (collection/modland.py:~100-114); HVSC `parse` makes format "HVSC - Musicians/Games/Demos" (collection/hvsc.py:22-48); SNDH is constant "SNDH" (sndh.py:111); ASMA/Keygen/ZXArt map extension -> format (asma.py:91, keygenmusic.py:51, zxart.py:115). Collections reuse Modland's format names so songs merge and share replayers (docs/collections.md:60).
- Storage: SQLite, `catalogs/<id>.db` per collection (docs/collections.md:12), schema at src/bbmp/index.py:97-137: `files(id, collection, path, format, artist, album, name, hidden, md5, size, UNIQUE(collection,path))`, index `files_browse(format, artist, hidden)`, plus `formats` (counts per collection/format), `changes`, `lengths`, `extensions` (ext -> format), `chips`, `notes`, and FTS5 `fts(name, artist, album, format)` with `content='files'`, tokenizer unicode61 remove_diacritics.
- Build: `index.build/_build_one/_fill` (index.py:287-460) writes a tmp DB then swaps; a `Shrank` guard refuses a suddenly much smaller list (index.py:275-285). Update orchestration in `src/bbmp/catalogs.py` (update/prepare/choose, lines 123-239; "due" schedule line 239). Listing sources: Modland allmods_md5.zip + allmods.zip (sizes) + daily changelogs (modland.py:27-33); SNDH reads the yearly zip listing (sndh.py:2-6, 95-111).
- Opening: `Index` attaches all chosen DBs and builds TEMP VIEWs that union them (index.py:561-700; docs/collections.md:12 notes SQLite's 11-file attach limit).
- Navigation: Collection -> Format -> Artist -> Songs: `Index.formats()` (1058), `artists(fmt)` (1063), `songs(fmt, artist)` (1090), `all_artists` (1077). Platform and chip are VIEWS over the same tree: `platforms.py` (static format -> platform/chips tables; `platforms.matches`), per-song chips only for formats where the file names its chip (SID 6581/8580, VGM clocks, DMF system byte) in the `chips` table, filled by `song_chips.py` (header lines 1-40) from the first 4096 bytes. `view_formats / view_counts / view_condition` (index.py:939-1220). Genre: none (grep for "genre" only finds an export tag = format, export.py:259, mpris.py:171).
- Search: FTS5 prefix match. `search_query` (index.py:166-188) turns "jest -remix artist:\"purple motion\" format:ahx" into `"jest"* AND ... NOT ...` with column filters (`SEARCH_FIELDS`, line 148: artist/by/format/title/album/game). `platform:` and `chip:` are peeled off by `view_terms` (155) and become SQL conditions joined to `chips` (`_searched`, 1110-1146). `search()` limit 5000 (1148).
- Identity: song key = `"<collection>:<path>"` (docs/collections.md:25-37); `Index.resolve(key)`, `relocate`, `moved` (by md5) follow moved files.
- Downloads/cache: `Fetcher` (src/bbmp/fetch.py:66-419). `get(key, companions)` (136-168) returns a local path, hits cache at `~/.cache/bbmp/files/<id>/<path>` or kept-music folder, downloads missing files (parallel via `_download_all` 170), md5-checks against the catalog (`_download_now` 378). LRU trim by mtime ("last used" via utime), `trim(limit, keep)` (222) never deletes favorites/queue/last-minute files. Transports: FTP/HTTP and `Mirrors` that rank servers by time-to-first-byte (collection/transports.py, docs/collections.md:~74-86). "Companions" (samples/instruments next to a song) fetched with the song (companions.py). Prefetch of next song in player.py:279-308. NOTE: `src/bbmp/downloads.py` is NOT song download; it is optional replayer data (instrument banks, Amiga players) fetched on demand.

## 2. Replayer helper protocol
Two mechanisms.

A. Pipe helpers (C/C++ executables), src/bbmp/backends/pipe.py:
- Launch: `<helper> [engine] <file> <track> <rate> <start_ms>` (pipe.py:~170-176; usage in csrc/amiga/bbmp-amiga.cpp:120-131, argv[1]=engine name, then path, track, rate, optional start_ms). stdin /dev/null, stderr discarded.
- Output: first line = JSON header, then raw s16le stereo until EOF. Header (amiga main, bbmp-amiga.cpp:~150-165): `tracks, title, author, type, duration_ms, comment, names[]`; also read by Python: `program`, `facts{}`, `error` (pipe.py:~192-230). Error = `{"tracks":0,"error":"..."}` (bbmp-amiga.cpp:82).
- No command channel: subsong select and seek are done by RESTARTING the process with new `track` / `start_ms` (pipe.py `select_subsong`, `seek`). Position is counted by the player from frames read. No per-channel levels or voice info come back from pipe helpers (`channel_levels` is the base default `None`, base.py:`Decoder.channel_levels`); only Remote backends provide them.
- Hardening: first line capped 64 KiB, 10 s stall kill (`STALL_SECONDS`), text clipped to 2000 chars, tracks capped 10000, leftovers swept from /tmp.
- Registry `HELPERS` maps backend name -> (exe, prefix, argv) (pipe.py:~60-120); `_own()` registers helpers with several engines. A helper may be absent ("left-out.txt" per package).
- Shared C++ contract, csrc/amiga/engine.h:11-41: `struct SongInfo{tracks,title,author,type,comment,duration_ms,names}`; `class Engine{ bool open(path, file_bytes, track, rate, SongInfo&, error); size_t render(int16_t* out, size_t frames); }` (fewer frames than asked = ended); self-registration via `REGISTER_ENGINE(name, make)` linked list; helpers `to_utf8` (Latin-1 fallback), `debug_on()`. Other csrc/* helpers follow the same argv+JSON+PCM protocol (stated in pipe.py:1-14); engine.h itself is shared only inside csrc/amiga (unconfirmed for other dirs).

B. Remote (big libs: libopenmpt, UADE, GME, libsidplayfp, SunVox), src/bbmp/backends/remote.py:
- `python -m bbmp.backends.remote <backend> <path> <lengths-json>` in the sandbox (remote.py:70-80); commands on stdin, one JSON per line: `read{frames}`, `subsong{n}`, `seek{seconds}`, `forever{on}`, `pattern{rows}`, `details`, `close` (serve loop, remote.py:~300-335).
- Reply framing: 4-byte length + JSON header + PCM body (docs at remote.py:7-9; MAX_HEADER 1 MiB, MAX_BODY 64 MiB). Header carries `levels` (per-channel 0..1, clamped, max 64, remote.py:143-152), `done`, `view` (pattern: current row + text lines), `facts`/`texts` (Info tab), `info` (updated TrackInfo when it changes, e.g. subsong), `never_ends`, `unsupported`, `needs_download`.
- Timeouts: 15 s open/seek, 3 s per read (WAIT, WAIT_READ). Crash = `read` returns b"" which ends the song.
- Decoder interface in-process: `Decoder.read/select_subsong/seek/channel_levels/details/loop_forever/pattern_view/close`, `TrackInfo{title,author,format,duration,subsongs,subsong,extra}` (src/bbmp/backends/base.py:21-89). RATE=48000, 16-bit stereo for ALL backends (base.py:13).
- Sandbox, src/bbmp/sandbox.py: bwrap (`--ro-bind / /`, `--unshare-all` = no network, `--die-with-parent`, `--new-session`, private /tmp, only needed home dirs bound; lines 437-452), fallback Landlock via `bbmp-shut` launcher with seccomp socket ban (docstring 9-27), macOS Seatbelt via /usr/bin/sandbox-exec (28-32), 2 GiB data memory limit (MEMORY_LIMIT, line 60), unsandboxed fallback with a warning, `BBMP_SANDBOX=0` to disable. Applied in both pipe.py (`sandbox.wrap`+`sandbox.popen`) and remote.py.

## 3. Audio output path (src/bbmp/audio.py, csrc/out/bbmp_out.c, player.py)
- Mixing: none in the player. Each backend renders final stereo 48 kHz s16 itself. Player-side processing only: volume x end fade (`ending.fade`), optional loudness leveller (`loudness.py`, LUFS measured on a 'preview' read-ahead; player.py:739-780) with numpy (`_play`, player.py:1023-1073). Resampling: none (helpers are told the rate; RATE fixed). Unconfirmed whether some backends resample internally.
- Chunking: `CHUNK = 2400` frames (50 ms) per render/write (player.py:39). Render loop = `_run` -> `_render_chunk` (385-412, 986-1021) in a dedicated thread.
- Backends: `PulseOutput` pa_simple blocking write, tlength 400 ms default because PipeWire only keeps ~1/3 (audio.py:55-75; comment explains 150 ms underruns). `MiniaudioOutput` calls `libbbmp-out` (csrc/out/bbmp_out.c): miniaudio ring buffer of `rate*buffer_ms/1000` frames (line 64), device callback copies from ring and plays silence on underrun (32-50), API: `open(rate, buffer_ms, null)`, blocking `write`, `latency`, `flush`, `drain`, `close`; default 300 ms. `BBMP_AUDIO=pulse|miniaudio|silent`; `NullOutput` for tests (audio.py:150-182).
- Latency compensation: displayed elapsed = played - `out.latency()`; scope/spectrum use audio delayed by latency from a `_recent` ring (player.py:1056-1064).
- VU/scope to UI: per-channel levels come from `decoder.channel_levels()` (list 0..1) after each chunk (player.py:1043 and read-ahead marks 721-737 so bars align with sound read ahead). Master L/R peaks computed from the output samples (`_peak`, 1049, 1076). Waveform for scopes/spectrum = last WAVE_FRAMES of delayed PCM stored in `Status.wave`. All land in the `Status` dataclass under a lock (`_set`, player.py:364-375).

## 4. TUI structure (src/bbmp/tui/)
- Textual app `ModlandApp` (tui/app.py:58) assembled from mixins: PlayingPart, BrowsePart, ListsPart, ArtistPart, SavingPart, ExportPart, SettingsPart (one file each in tui/). Dialogs are ModalScreens (dialogs.py, activity.py).
- Layout (app.py:215-255, TabbedContent): 1 Browse (three-pane OneLineList / SongTable / Static info + format Note), 2 Search (SearchBox + SongTable), 3 Queue, 4 Playlists, 5 Files (DirectoryTree), 6 History, 7 Info, 8 Artist, 9 Stats, 0 Settings. Always-visible `#now` NowPlaying (widgets.py:299, level meters, channel bars at line 387 using BARS blocks) and `#visual` Visualizer (widgets.py:427; modes in visuals.py:MODES = spectrum, bars, mirror, spectrogram, scope, scopes, channels, pattern, demo; renderers numpy -> Rich Text, ~1 ms each).
- Keys (app.py:114-158, docs/testers.md:54-71): Space pause, n/p next/prev, ]/[ subsong, ./, seek +-10 s, +/- volume, / search, b "by" view, r radio (random from current scope), Ctrl+R radio all, f favorite, s save/keep offline, a queue, N play next, l add to playlist, e export, c collection, m artist, g go to playing, i info, v cycle visuals, o loop forever, R repeat, S shuffle, ! "sounds wrong" report, ? help, q quit, 1-0 tabs.
- State flow: POLLING. `set_interval(1/12, self._tick)` (app.py:463); `_tick` (972-1000) calls `player.status()` (a locked copy of the Status dataclass, player.py:348) and pushes it into NowPlaying.show / Visualizer.show; throttles to 6 Hz when the terminal is behind (985-990). Commands from UI to player go through methods that enqueue to the player thread (`play_list, toggle_pause, seek, subsong ...`, player.py:202-260, handled in `_handle` 444). Background work (catalog update, history, stats) uses worker threads + `call_from_thread`. No event bus for player->UI (unconfirmed beyond grep of app.py/player.py).
- Also: mpris.py (desktop now-playing), cli.py (non-TUI commands such as `bbmp update`, `bbmp formats`).

## 5. Format / player registry
- `BACKEND_BY_FORMAT: dict[format name -> backend]` in src/bbmp/backends/formats.py:7 (generated by tools/format_census.py from real files; ~425 lines), `UNSUPPORTED_FORMATS` set (line 429). Key is the CATALOG FORMAT NAME (Modland's folder names, shared by other collections), not the extension.
- `backend_for(fmt)` (backends/__init__.py:154): exact name, else parent before " - " (`_parent`, 146) so "Video Game Music - Sega Megadrive" and "HVSC - Musicians" fall back to a family entry. `is_supported` (159).
- `open_song(path, fmt, lengths, local)` (176-222): `first` backend from the table; local files (no catalog) use extension only: `LOCAL_BACKENDS` {.vgm,.vgz} then `Index.guess_format(name)` (index.py:1488) which uses the `extensions` table built from the catalog: `_extension_formats` (index.py:208) picks the most common format per extension AND per name prefix (Amiga `mdat.x`), `file_keys` (191). Then an ordered try list: own helpers use `[first, *ALSO[first]]`; otherwise `[first]+FALLBACK`; first success wins, errors accumulated; a "mend" pass retries a slightly damaged file (backends/mend.py); `NeedsDownload` remembered and re-raised if nothing plays.
- Backend name -> opener: `LOCAL_OPENERS` (in-process/remote libs) and `HELPERS` (pipe.py).
- docs/format-notes.toml is NOT used for matching: per-format quality metadata (status verified/compared/unchecked/faults/off/no, `all`, `basis`, `note`, `nosong`; header lines 1-17), rendered into docs/formats.md by tools/format_status.py and read at runtime by format_notes.py to show "how well its format plays" in the Info tab.
- Magic-byte matching: not used for selection in the registry (confirmed by reading formats.py/__init__.py); replayers/helpers themselves reject wrong files with `error`. Companion/psf libs detection in psf.py, companions.py (not read in depth).

## Takeaways for a C player (opinion)
- Reusable idea: tiny engine ABI (open + render + metadata + optional seek/levels) with self-registration; process isolation optional per engine.
- Catalog: sqlite+FTS5 per collection is simple and fast; add a `genre`/`chip` column to files instead of bbmp's side table if wanted.
- bbmp pipe protocol cannot return levels/position/voices and seeks by restart; a C design should define a command channel or in-process vtable with `channel_levels`, `seek`, `subsong` from the start.
- UI polling a snapshot struct at 12 Hz is simple and decoupled; replicate with an atomic/locked `status` struct.
