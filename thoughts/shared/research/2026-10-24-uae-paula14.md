# paula14 and paula play runs on FS-UAE after 741d806 (I138a drain)

Rig: 2026-10-24-uae-rig-recipe.md. Binary: build/amiga selecta-cli built 21:38:16, after p14_sink.c (21:38:13), so it contains the drain. Song WORK:songs/ambient.mod, `selecta-cli play ... --seconds N`, stdout to out.txt, per-run wait up to ~9 min. Boot takes a few minutes each time.

| Run | Result |
|---|---|
| paula, default rate 44100, 1 s | PASS: `callbacks=0 frames=44100`, rc=0 |
| paula, --rate 200000, 1 s | PASS: frames=200000, rc=0 |
| paula14, --rate 22050, 1 s | PASS on real custom-chip bus: `frames=22050`, rc=0 (open, pump, close drain, DMA stop all return) |
| paula14-shadow, default rate, 1 s | PASS: frames=44100, rc=0 |
| paula14, default rate 44100, 1 s | HANG (>13 min, no rc line) |

| paula14, --rate 40000, 1 s | HANG |

## Findings
- I138a close drain is not the hang: paula14 with a valid rate (22050, period 160) runs the full open, submit, close-drain, DMA-stop sequence on the emulated custom chip and exits rc=0. The drain itself is bounded by host clock_ms; it ran fine.
- The earlier "paula14 did not return" report was the default 44100 Hz run. `sel_p14_period_for_rate(44100)` = 80 < SEL_PAULA_PERIOD_MIN 113 and paula14 is strict (kind flag 1), so `sel_p14_open` returns -1 and play.c takes the "no output device" path (rc 77). That path hangs.
- The hang is not paula14 specific and not the sink: `--output paula --seconds 0` (open succeeds, pump never called) hangs too. Common factor of every hang: the output pump was never called, then `sel_engine_destroy` (apps/selecta-cli/play.c, both the failed-open return and the normal tail after a zero-length loop). Every run that pumped at least once exited. Suspected location: engine start/destroy handshake that only completes when the audio side pumps (sel_engine_destroy -> close_slot, src/engine/engine.c:4654), unverified; no debug print was built to confirm. stderr output, find_output failure and start_song failure all return.
- Separate defect: paula14 at 44100 Hz is rejected (strict min period 113 means max ~31 kHz), so `--output paula14` with the CLI default rate can never play; use `--rate 22050` (or 31000) on the rig.
