# I899: which TLS layer on Amiga

## Facts from the repo
- `src/library/net/tls.[ch]`: desktop links vendored mbedTLS (`third_party/mbedtls`, 5.4 MB of library source, config `selecta_mbedtls_config.h`); Amiga compiles `SEL_NO_TLS` stubs (`src/library/CMakeLists.txt:43`) that answer `SEL_TLS_E_UNAVAILABLE`. The API surface a replacement must fill is small: `sel_tls_open`, `sel_tls_open_insecure`, `sel_stream_send/recv/close`, driven over the socket table with deadline BIO callbacks.
- Config already sets `MBEDTLS_NO_PLATFORM_ENTROPY` + `MBEDTLS_ENTROPY_HARDWARE_ALT` (lines 32-33) and says the Amiga client "brings its own `mbedtls_hardware_poll`". No Amiga `mbedtls_hardware_poll` exists in src/plugins (grep, UNVERIFIED where the desktop one lives). So mbedtls on Amiga is a fourth candidate and is already vendored.
- Selecta licence: MIT (LICENSE).
- DCTelnet `src/crypto` (read-only): aes.c (93 lines, no GCM), sha256, x25519, rsa (PKCS#1 v1.5 verify only, 32 lines), bignum + 68k `bn_muladd.s`, `random.c` (SHA-256 pool, `Random_Add`). About 1150 lines total. Missing for TLS: record layer, handshake state machine, AES-GCM (GHASH) or ChaCha20-Poly1305, HMAC/HKDF/PRF, ECDHE P-256 (only x25519; Chromecast and most servers offer P-256 ECDSA/RSA with ECDHE, x25519 is optional), ECDSA verify, X.509/ASN.1 parser, hostname match, CA store, SNI, session handling. DCTelnet licence file not found in the dir (UNVERIFIED, ask owner; same author so likely compatible).

## Needs
- Chromecast (port 8009): TLS 1.2, self-signed device cert, no verification (`sel_tls_open_insecure`): needs ECDHE + AES-GCM (or ChaCha) and cert parse only to skip it.
- https mirrors and DEViLBOX login: verified chain, SNI, modern servers (TLS 1.2 minimum, often 1.3-only edge configs, ECDSA P-256 and RSA 2048/4096 certs, Let's Encrypt chains).

## Entropy per candidate (security gate)
No TLS enabled until a seeded source exists. Common Amiga sources, mixed (none alone is a true RNG; the sum is the entropy budget):
1. timer.device E-clock (`ReadEClock`) low bits sampled around events: network packet arrival, disk reads, user input; jitter, collect >= 256 samples, hash.
2. input.device event timing and mouse deltas (only when UI is used; a headless boot has little).
3. CIA timer counters and VPOSR/VHPOSR beam position at event times (DCTelnet's `StirTime` uses beam, `IdleCount`, `DispCount`, `DateStamp`: weak individually).
4. Persisted seed file `S:selecta.seed` rewritten each run (mix on boot, replace on exit) to cover boot-time poverty; never the only source.
Per candidate:
- mbedTLS: implement `mbedtls_hardware_poll` returning a SHA-256 of the pool above; CTR_DRBG seeded from `mbedtls_entropy_func` (already wired in tls.c). Feed the pool before first handshake; refuse (`SEL_TLS_E_INIT`) if fewer than ~256 timing samples gathered.
- AmiSSL: seeds its own RNG internally, mechanism not documented on the page (UNVERIFIED); we must still call `RAND_add` with the pool above and check `RAND_status`. Do not trust an unstated default.
- AmiTLS/BearSSL: BearSSL needs the app to seed `br_hmac_drbg`/system seeder; page names no source (UNVERIFIED). Seed with the pool above.
- DCTelnet custom: `Random_Add` pool exists; same four sources feed it.
Conclusion: entropy is our job for every candidate; one shared Selecta module `amiga_entropy.c` (pool, seed file, sample collectors) feeds whichever library. Estimates of bits per sample are UNVERIFIED; the rig test (below) measures the sample distribution.

Cast HTTP token (`plugins/shared/cast/cast_http.c token_make`): reads `/dev/urandom` (absent on Amiga), then clock + stack address + counter, which is guessable. It protects a file URL served to the local network. Feed it from the same `amiga_entropy` pool (`sel_entropy_bytes(buf,16)`), refuse to serve when the pool is below threshold, and use 128-bit tokens from the pool hashed with MD5 as today.

## Recommendation
mbedTLS from the vendored tree on Amiga (candidate 4), TLS 1.2 + 1.3 client only, ECDHE-ECDSA/RSA with AES-128-GCM and ChaCha20-Poly1305, P-256/x25519, plus the shared `amiga_entropy` module. Reasons: tls.c already targets it, same verification code on both platforms (one trust model, one place for the insecure Chromecast path), no user-installed dependency, mature and reviewed, licence matches (vendored already). Cost: slowest bignum (portable C); mitigate with an `MBEDTLS_MPI_MUL_ASM`-style 68k hook reusing DCTelnet's `bn_muladd.s` approach (copy the technique, not a dependency), and restrict to ECDHE P-256/x25519 to avoid 2048-bit RSA key exchange cost. AmiSSL stays the fallback if rig numbers on the 020 are unusable (it has 020-040 asm and a shared library) but needs a user install and a second socket path. AmiTLS is rejected for now (1.2 only, hostname checks partial, immature). A custom TLS on DCTelnet primitives is rejected: the primitives are about 10% of what TLS needs and unreviewed crypto is the wrong place for savings.
Size/time numbers above are UNVERIFIED until the rig run.

## Rig measurement plan (later batch; purpose text "I899 session: TLS handshake and throughput")
Build a tool `tlsbench` (host-compiled for 68k, same code as tls.c) with modes for each candidate that was built (mbedTLS first, AmiSSL second).
1. Start rig 020 (A1200-class, 68020 14 MHz-ish config used by the project) and rig 060 (`rig.py start --max`), rig 2 with `--ram 256`; silent audio.
2. Server on the Mac: `openssl s_server` with a P-256 ECDSA self-signed cert, TLS 1.2 forced, and a second with TLS 1.3; plus a 16 MB file endpoint.
3. Handshake time: 20 handshakes per suite (ECDHE-ECDSA-AES128-GCM, ECDHE-RSA-AES128-GCM, ChaCha20, x25519 and P-256), record median and p95 in ms using timer.device E-clock; log first handshake separately (DRBG seeding cost).
4. Throughput: fetch the 16 MB file, MB/s per cipher; record CPU idle share from `SysBase->IdleCount`.
5. Real servers: one https mirror and the DEViLBOX login host, verified chain with Mozilla CA bundle; record chain verify time and peak memory (`AvailMem` delta).
6. Entropy: dump 4096 raw samples from each source, compute mean/histogram of low bits, estimate min-entropy per sample; confirm pool reaches threshold in under 5 s of normal use.
7. Binary size: stripped hunk size of the TLS code per candidate.
Pass line (proposal, owner to confirm): handshake under 3 s on 020 with P-256; under 0.5 s on 060; throughput at least 60 KB/s on 020 (FLAC streaming needs less on mirrors, album art needs only handshakes).
Clean up: stop rigs and delete rig dirs after the last command.
