output build/web; SDL3 through the Emscripten port `-sUSE_SDL=3`, `-pthread`, `-sPROXY_TO_PTHREAD`, `-sOFFSCREENCANVAS_SUPPORT`,
`-sALLOW_MEMORY_GROWTH`, `-sFETCH`). Configure succeeds. Build: about 820 of 1133 units compiled before I stopped it; the link of

## SDL3 GPU on the web (decides I694p)

Answer: NO WebGPU backend. Evidence, from the SDL source the Emscripten port downloads
(`/opt/homebrew/Cellar/emscripten/4.0.16/libexec/cache/ports/sdl3/SDL-release-3.2.22`, port definition `tools/ports/sdl3.py`,
VERSION 3.2.22). This repo vendors no SDL source; the host build uses Homebrew SDL3 3.4.x.
- `src/gpu/` holds only `d3d12`, `metal`, `vulkan` plus `SDL_gpu.c`, `SDL_sysgpu.h`. No webgpu directory.
- `grep -i webgpu` over `src/gpu/SDL_gpu.c`, `CMakeLists.txt`, `include/SDL3/SDL_gpu.h`, `cmake/*.cmake`: no hits.
- The port's pre-generated `SDL_build_config.h` has SDL_GPU_D3D12, SDL_GPU_VULKAN, SDL_GPU_METAL all `#undef`.
- Shader formats in `SDL_gpu.h`: SPIRV, DXBC, DXIL, MSL, METALLIB only.

Consequence: `SDL_CreateGPUDevice` cannot succeed in the browser, so `plugins/viz/krakatoa/sdl/krk_smoke_gpu.c` (SDL_GPU compute
pipelines and buffers) cannot run as is. Only the Krakatoa file uses SDL_GPU (grep of plugins, src, apps, cmake). I694p must
choose: WebGPU compute through Emscripten's own `webgpu.h` (WGSL port of the shaders) or a CPU/fragment fallback. Unverified:
whether SDL 3.4 or later adds a WebGPU backend; the port pins 3.2.22 and I did not check upstream.
